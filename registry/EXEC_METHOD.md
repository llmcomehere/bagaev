# EXEC-1 — исполнимое соответствие

Метрика показывает, какие нормативные правила подтверждены исполнением и насколько им соответствует реализация.

## 1. Что считается

| Показатель | Определение |
| --- | --- |
| **Покрытие правил** `a/b` | `b` — число правил в [spec/conformance-manifest.json](../spec/conformance-manifest.json); `a` — правила со статусом EXECUTABLE без пометки `partial`, у которых **все** перечисленные случаи проходят у эталона и имеют `origin` ≠ `derived`. Правило с `partial: true` (случаи покрывают только часть его содержания) не считается покрытым, пока пометка не снята |
| **Эталон** `ref c/d` | `d` — число случаев `conformance/cases/**/case.json`, применимых к эталону; `c` — сколько из них проходит |
| **Компилятор** `rust e/f` | то же для реализации на Rust (с Ф9), отдельно по уровням L1/L2 |
| **Пилот** | статус варианта A/B/C и общий вывод: `NOT_RUN`, `IN_PROGRESS`, `PASS`, `FAIL` или `INCONCLUSIVE` ([план, Ф7–Ф8](PLAN.md)) |
| **Решения** (только в JSON) | число карточек D-xx в статусах accepted / частично accepted / proposed ([07-decisions.md](../spec/architecture/07-decisions.md)) |

Строка итога:

```text
EXEC-1: правил покрыто a/b; ref c/d; rust e/f; пилот <статус>
```

## 2. Происхождение ожиданий

Поле `origin` каждого случая:

- `independent` — ожидание выведено из спецификации до запуска реализации;
- `model:<путь>#<id>` — ожидание взято из замороженной модели `models/` или её фикстуры;
- `derived` — ожидание снято с самого эталона. Такие случаи годятся для регрессии, но **в покрытие правил не идут**: одинаковая ошибка эталона и ожидания не должна выглядеть подтверждением.

## 3. Что не считается

- **Число тестов, файлов и строк.** Покрытие считается по правилам, а не по случаям.
- **Случай без ссылки** `spec` на существующий документ. `check.py` отвергает его при проверке корпуса.
- **Правило с пометкой `NOT_YET_EXECUTABLE`.** Оно входит в знаменатель `b` и остаётся непокрытым.
- **Пустой набор.** `0/0` — это NOT_RUN, а не PASS: `check.py --exec` выдаёт для него SKIP с причиной.
- **Прогон модели `models/`.** Это свидетельство отдельного контракта, а не исполнение языка.

Знаменатель `b` растёт вместе со спецификацией. Поэтому `a/b` — доля покрытия, а не процент продвижения трека. Рост `b` без роста `a` — честный сигнал, что правила опережают проверки.

## 4. Как получить

```bash
python3 tools/exec_report.py            # прогон корпуса, запись registry/exec-progress.json
python3 tools/check.py --exec           # тот же прогон без записи; FAIL, если exec-progress.json устарел
```

Значение зависит от того, какие реализации доступны. Например, собранный `compiler/target/release/bagc` добавляет строку rust. Поэтому `exec-progress.json` пересчитывается в том окружении, где делается коммит.

Корпус и контракт исполнителя — [conformance/README.md](../conformance/README.md).
