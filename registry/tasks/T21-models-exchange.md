# T21 Спроектировать вызовы моделей обучение и формы обмена

Цель: **G10**. Волна: **EXT**. Профиль: **EXT**.

**Статус и основания готовности** ведутся в [оценках](../../docs/verification.md) и [прогрессе](../../docs/verification.md), исполнимость — в [EXEC-1](../exec-progress.json); наличие этой карточки не означает выполнение.

## Результат

Определить приложения с моделями и специальные форматы обмена как явные профили, сохранив исполнимость обычной программы без LLM.

Контекст: [основа языка](../../spec/foundation.md), [цели](../GOALS.md), [дорожная карта](../PLAN.md).

## Входы и зависимости

Предшественники: [T16](T16-spec-freeze.md)

- Семантика эффектов и runtime V1
- Конкретные задачи inference/training/exchange
- Версионируемые модели, данные и схемы

Рабочий материал: [02-language-runtime.md](../../spec/architecture/02-language-runtime.md). Его нужно завершить и проверить, а не считать готовой нормативной спецификацией.

## Решения, которые необходимо закрыть

- Контракты недетерминированного model-call и лимиты
- Происхождение и версии training data/model artifacts
- Схемы обмена, streaming, backpressure и совместимость

## Порядок работы

1. Определить вызов модели как явный эффект с параметрами, бюджетами, исходами и правами.
2. Разделить воспроизведение записанного ответа и новый вызов модели.
3. Для обучения определить dataset/model lineage, checkpoints, ресурсы и критерий результата.
4. Для обмена определить canonical schemas, версию, частичные сообщения, порядок и отказ.
5. Проверить обработку непригодного результата, исчерпания бюджета, прерывания и смены версии модели/схемы.

## Критерии приёмки

| ID | Проверяемое условие |
| --- | --- |
| T21-C01 | Модельный ответ не изменяет семантику исходного языка сам по себе. |
| T21-C02 | Повтор inference/training не объявляется детерминированным replay без оснований. |
| T21-C03 | Checkpoint содержит достаточные версии данных и окружения для заявленной воспроизводимости. |
| T21-C04 | Несовместимый формат обмена даёт явную диагностику. |

## Обязательные отрицательные случаи

- Смена модели молча повышает успешный прошлый тест до доказательства новых ответов.
- Потерянная часть stream считается полным результатом.

## Основание завершения

Для каждого критерия сохранить точные версии предметов, входы, метод, ожидаемый и фактический результат. Лог выполненной проверки отличается от проекта проверки. Ревью должно проверить согласованность с зависимыми спецификациями; нулевое число замечаний без просмотра не является свидетельством.

Задача получает `done`, когда её выходы существуют, все обязательные критерии подтверждены допустимыми evidence и результаты приняты по действующим правилам проекта. Подготовка текста даёт `review`, а не автоматически `done`. Для изменения внешних систем нужны соответствующие полномочия; карточка не предоставляет их.

## Если условие не выполнено

Выделить ограниченный профиль и объявить непокрытое; не добавлять зависимость от LLM в обычное исполнение V1.
