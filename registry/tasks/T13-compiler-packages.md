# T13 Спроектировать компилятор сборку пакеты и библиотеку

Цель: **G07**. Волна: **W5**. Профиль: **V1**.

**Статус и основания готовности** ведутся в [едином реестре](../track.json) и [прогрессе](../../docs/verification.md); наличие этой карточки не означает выполнение.

## Результат

Определить полноценный путь исходник→проверенная программа→исполнение и границы повторно используемых модулей.

Контекст: [основа языка](../../spec/foundation.md), [цели](../GOALS.md), [дорожная карта](../PLAN.md).

## Входы и зависимости

Предшественники: [T03](T03-source-ir.md); [T04](T04-types-semantics.md); [T05](T05-effects-contracts.md); [T06](T06-runtime.md)

- Source/IR и семантика
- Эталонная машина T06
- Платформы и поддерживаемые эффекты

Рабочий материал: [02-language-runtime.md](../../spec/architecture/02-language-runtime.md). Его нужно завершить и проверить, а не считать готовой нормативной спецификацией.

## Решения, которые необходимо закрыть

- Первый target и язык реализации после аудита существующего кода
- Форматы модулей, линковки, lock-файла и ABI
- Минимальная стандартная библиотека и граница FFI

## Порядок работы

1. Специфицировать стадии parse/resolve/type/effect/lower/link/emit и формат диагностик.
2. Определить интерфейсы модулей, видимость, generic instantiation и совместимость артефактов.
3. Задать разрешение зависимостей с точными lock, форматы пакетов и воспроизводимость сборки.
4. Определить ABI/FFI с явными эффектами, памятью, ошибками и ограничениями покрытия.
5. Составить нормативный API стандартной библиотеки с контрактами и негативными примерами; оптимизации проверять относительно эталона.

## Критерии приёмки

| ID | Проверяемое условие |
| --- | --- |
| T13-C01 | Каждая стадия имеет вход, выход, ошибки и версии форматов. |
| T13-C02 | Lock определяет точные зависимости, а не плавающие названия. |
| T13-C03 | Оптимизация сохраняет наблюдаемые результаты эталона в заявленной области. |
| T13-C04 | FFI не скрывает эффекты и требования к памяти. |
| T13-C05 | API библиотеки полностью перечислен либо исключён диагностикой. |

## Обязательные отрицательные случаи

- Сборка зависит от незафиксированной версии пакета.
- Native/FFI обходит capabilities и становится невидимым графу.

## Основание завершения

Для каждого критерия сохранить точные версии предметов, входы, метод, ожидаемый и фактический результат. Лог выполненной проверки отличается от проекта проверки. Ревью должно проверить согласованность с зависимыми спецификациями; нулевое число замечаний без просмотра не является свидетельством.

Задача получает `done`, когда её выходы существуют, все обязательные критерии подтверждены допустимыми evidence и результаты приняты по действующим правилам проекта. Подготовка текста даёт `review`, а не автоматически `done`. Для изменения внешних систем нужны соответствующие полномочия; карточка не предоставляет их.

## Если условие не выполнено

Оставить интерпретатор первым target или сократить библиотеку; промышленный backend не обязателен для первого опыта, но его границы должны быть определены.

## Связь с общей готовностью

Проверить влияние пересмотра на прямых и обратных потребителей этой спецификации. Изменённые условия и оставшиеся вопросы внести в единый реестр. Статусы спецификации, реализации, проверки и выпуска вести отдельно.

## Исследовательский вход R03

[Законы OBS и replay](../../spec/links/06-law-checking.md) дают частичный проект сохраняющих преобразований для критерия T13-C03: определены выбранные наблюдения, предпосылки, точные шаги и проверка ограниченной правки кода. Конечный опыт (`r07:results/law-profile/report.json`) сравнивает исходные и преобразованные программы. Полный оптимизатор, стадии compiler pipeline, форматы пакетов, FFI и библиотека V1 остаются открытыми.

## Исследовательский вход R04

Hygienic strict-let lowering отделён от runtime и ограничен preflight по размеру/глубине. Structural checker воспроизводит преобразование, а независимый direct oracle проверяет выбранные исходы. Полный compiler contract V1 остаётся открытым. [Контракт](../../spec/links/07-call-composition.md), [API](../../models/r07-core/experiments/call-profile/API.md) и фактический отчёт (`r07:results/call-profile/report.json`) относятся к ограниченному CALL-0.1. Критерии карточки не закрыты. Следующая R05 объединяет результаты с полным feature ledger и общей семантикой V1.

## Исследовательский вход R05

[SEM-0.1](../../spec/language/semantic-core.md) явно запрещает перенос OBS/R03 value/error/trace equivalence на полный V1 без budget/cancel/settlement contract. [Реестр](../feature-ledger.json) сохраняет закрытые API stdlib, packages, ABI/FFI и platform targets как обязательные незавершённые результаты. Они не выполнены конечной AUTH-моделью.

## Исследовательский вход R06

[CORE машина](../../spec/runtime/core-machine.md) фиксирует logical charges и cancel boundaries, которые backend не может молча изменить при inlining/TCO/type erasure. [IR contract](../../spec/ir/typed-core.md) отделяет research input от source lowering/codec. Compiler/stdlib/FFI/locks и simulation не объявлены готовыми.

## Исследовательский вход R07

[DATA API](../../models/r07-core/experiments/data-core/API.md), [runtime work](../../spec/runtime/data-work.md) и [codec](../../spec/data/value-codec.md) уточняют исследовательский API библиотеки и требования к cost-preserving backend. [Authorship bridge](../../spec/data/authorship-values.md) композиционен на уровне готовых jobs; выразимость той же программы исходным языком не проверена. Package manager, ABI/FFI и полный stdlib остаются исходными обязательствами.
