# T08 Определить извлечение связей покрытие и свидетельства

Цель: **G04**. Волна: **W3**. Профиль: **V1**.

**Статус и основания готовности** ведутся в [оценках](../../docs/verification.md) и [прогрессе](../../docs/verification.md), исполнимость — в [EXEC-1](../exec-progress.json); наличие этой карточки не означает выполнение.

## Результат

Сделать происхождение и область знания машиночитаемыми и поддерживаемыми при изменении программы.

Контекст: [основа языка](../../spec/foundation.md), [цели](../GOALS.md), [дорожная карта](../PLAN.md).

## Входы и зависимости

Предшественники: [T02](T02-program-model.md); [T03](T03-source-ir.md); [T05](T05-effects-contracts.md)

- Схемы T02 и IR T03
- Эффекты/контракты T05
- Перечень типов связей

Рабочий материал: [01-program-model.md](../../spec/architecture/01-program-model.md). Его нужно завершить и проверить, а не считать готовой нормативной спецификацией.

## Решения, которые необходимо закрыть

- Канонические виды рёбер и допустимые концы
- Алгоритм извлечения и декларации для каждой конструкции V1
- Footprint evidence, покрытие и словари статусов

## Порядок работы

1. Задать таблицу extraction rule→IR construct→edge kind→coverage.
2. Разделить структурные выводы, декларации и наблюдения исполнения.
3. Определить индексы обратных ссылок и зависимостей результатов извлечения.
4. Специфицировать EvidenceRecord и применимость относительно вопроса, snapshot и StateRef.
5. Проверить инкрементальное обновление против полного пересчёта на конечном корпусе.

## Обязательные отрицательные случаи

- Общий confidence используется вместо основания.
- Изменение конфигурации не инвалидирует зависимый вывод.

## Основание завершения

Для каждого критерия сохранить точные версии предметов, входы, метод, ожидаемый и фактический результат. Лог выполненной проверки отличается от проекта проверки. Ревью должно проверить согласованность с зависимыми спецификациями; нулевое число замечаний без просмотра не является свидетельством.

Задача получает `done`, когда её выходы существуют, все обязательные критерии подтверждены допустимыми evidence и результаты приняты по действующим правилам проекта. Подготовка текста даёт `review`, а не автоматически `done`. Для изменения внешних систем нужны соответствующие полномочия; карточка не предоставляет их.

## Если условие не выполнено

Увеличить coverage gap или исправить извлечение; запрещено уменьшать неизвестность простой сменой статуса.

Проверить влияние пересмотра на прямых и обратных потребителей этой спецификации. Изменённые условия и оставшиеся вопросы внести в единый реестр. Статусы спецификации, реализации, проверки и выпуска вести отдельно.

## Исследовательская проработка · 22 октября 2026

Вход для продолжения: [DRAFT LNK-0.3](../../spec/links/README.md), [32 детализированных требования](../data/links/link-requirements.json) и выводы R01 и R02. Эти материалы уточняют проект, но не закрывают критерии карточки.

Конечная Python-модель действительно исполнена; её ручные факты и синтетические основания не подтверждают извлечение из bagaev. Совместимость с прежним кодом не требуется (D64), а нормативная приёмка — завершённых входов и собственных проверок этой задачи.

R02 добавляет [исполняемый AST и автоматическое извлечение](../../spec/links/05-executable-profile.md) с независимым oracle. Это исследовательский профиль с явными границами, не полный IR bagaev. Сохранение исхода включает ошибку и trace; требования остаются отдельными обязательствами.

## Исследовательский вход R03

[R03](../../spec/links/06-law-checking.md) добавляет происхождение каждого уточнения: исходный контекст, точные шаги и каталог законов. Сборка общего графа из таких summaries и их перенос через вызовы — следующий исследовательский шаг R04. Фактическая проверка (`r07:results/law-profile/report.json`) имеет ограниченный корпус и не закрывает критерии карточки.

## Исследовательский вход R04

Use автоматически композируется через функции. Closure фиксирует найденные, внешние и отсутствующие targets; обратный query получает всех известных транзитивных consumers. Project API пока выполняет полный rebuild. [Контракт](../../spec/links/07-call-composition.md), [API](../../models/r07-core/experiments/call-profile/API.md) и фактический отчёт (`r07:results/call-profile/report.json`) относятся к ограниченному CALL-0.1. Критерии карточки не закрыты. Следующая R05 объединяет результаты с полным feature ledger и общей семантикой V1.

## Исследовательский вход R06

Обоснование R06 выделяет будущие capture/call-target/scheme/semantics dependencies для функций как значений. Forward facts и reverse indexes должны происходить из одних записей; observed runtime targets не заменяют полный static set. Extraction для CORE ещё не реализован, прежние LNK results не расширены.

## Исследовательский вход R07

Исследование DATA разделяет nominal identity, projection, variant coverage, key order, predicate, codec layout и work profile как будущие семейства зависимостей. Изменение поля может не менять значение проекции, но identity/codec/work obligations рассматриваются отдельно. Provider, extraction и incremental update этих семейств не реализованы в R07.
