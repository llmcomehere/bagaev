# T18 Определить поставку совместимость и эксплуатацию

Цель: **G09**. Волна: **W6**. Профиль: **V1**.

**Статус и основания готовности** ведутся в [едином реестре](../track.json) и [прогрессе](../../docs/verification.md); наличие этой карточки не означает выполнение.

## Результат

Включить в полный язык правила поставки, поддержки форматов и реального использования инструментария.

Контекст: [основа языка](../../spec/foundation.md), [цели](../GOALS.md), [дорожная карта](../PLAN.md).

## Входы и зависимости

Предшественники: [T01](T01-scope.md); [T13](T13-compiler-packages.md); [T14](T14-developer-tools.md)

- Профили и платформы
- Toolchain/packages T13
- CLI и диагностика T14

Рабочий материал: [06-specification-completeness.md](../../spec/architecture/06-specification-completeness.md). Его нужно завершить и проверить, а не считать готовой нормативной спецификацией.

## Решения, которые необходимо закрыть

- Формат дистрибутива, поддерживаемые версии и платформы
- Политика обновлений source/IR/packages/protocol
- Обязательная документация, примеры и границы расширений

## Порядок работы

1. Определить установку, проверку окружения, воспроизводимую сборку и удаление временного состояния.
2. Задать матрицу совместимости форматов, порядок миграции проектов и диагностируемый отказ старых инструментов.
3. Определить выпуск, происхождение артефактов, проверку целостности и recovery, соразмерные профилю.
4. Спроектировать справочник, учебный маршрут и минимальный сторонний проект.
5. Определить процедуру сообщений об ошибках и минимальные воспроизводимые данные без непреднамеренного раскрытия проекта.

## Критерии приёмки

| ID | Проверяемое условие |
| --- | --- |
| T18-C01 | Каждый формат и протокол имеет версию и правило несовместимости. |
| T18-C02 | Обновление инструмента не меняет молча смысл существующей программы. |
| T18-C03 | Проект восстанавливается из объявленного комплекта входов. |
| T18-C04 | Чистая установка и создание минимального проекта имеют проверяемый маршрут. |
| T18-C05 | Публикация/развёртывание не входят автоматически в приёмку исходника. |

## Обязательные отрицательные случаи

- Новый compiler читает старый IR иначе без ошибки версии.
- Обновление необратимо меняет данные без определённого восстановления.

## Основание завершения

Для каждого критерия сохранить точные версии предметов, входы, метод, ожидаемый и фактический результат. Лог выполненной проверки отличается от проекта проверки. Ревью должно проверить согласованность с зависимыми спецификациями; нулевое число замечаний без просмотра не является свидетельством.

Задача получает `done`, когда её выходы существуют, все обязательные критерии подтверждены допустимыми evidence и результаты приняты по действующим правилам проекта. Подготовка текста даёт `review`, а не автоматически `done`. Для изменения внешних систем нужны соответствующие полномочия; карточка не предоставляет их.

## Если условие не выполнено

Сузить поддержку версий/платформ и явно объявить её; план выпуска не считать фактическим выпуском.
