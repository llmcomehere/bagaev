# Пробник пишемости — протокол

**Протокол пробника пишемости.** Перед измерением фиксируются параметры модели, задачи и пороги.

## 1. Вопрос

Может ли LLM, которая видела только шпаргалку [guide-llm.md](../../spec/language/guide-llm.md), писать на bagaev код, который проходит `bag check`, не хуже, чем она пишет TypeScript, проходящий `tsc --strict`? Это ворота K1 плана ([PLAN.md, B14](../../registry/PLAN.md)). Порог K1 зафиксирован в §4 до прогона.

## 2. Плечи и задачи

| Плечо | Язык | Что видит модель | Проверка |
| --- | --- | --- | --- |
| C | bagaev | системный промпт + `guide-llm.md` + условие + файлы контекста | `bag fmt --assign-ids` для файлов ответа, затем `bag check` проекта (контекст + ответ + скрытая проверка) |
| T | TypeScript 5 | системный промпт + условие + файлы контекста | `tsc --strict --noEmit --noUncheckedIndexedAccess` (контекст + ответ + скрытая проверка); компилятор 5.9.3 закреплён в [package.json](package.json) |

Двадцать задач `W01…W20` ([tasks/](tasks/), источник — [make_tasks.py](make_tasks.py)) одинаковы по смыслу для обоих плеч:

| Группа | Задачи |
| --- | --- |
| чистые функции, записи, перечисления, `Result` и `?`, обобщения, лямбды, карты, opaque, рекурсивные типы | W01–W09, W17–W20 |
| хранилище, команда, запрос, событие и обработчик | W10–W12 |
| контракт, `implements`, тест с `checks` | W13 |
| правка существующего кода: новый вариант, переименование поля, новый эффект | W14–W16 |

**Скрытая проверка интерфейса** не показывается модели. Модуль `probe` вызывает требуемые функции с точными типами. Для точек входа, которые код вызвать не может, сравниваются вид объявления, разрешённые типы параметров и результата (раскладка и запись имён роли не играют), фактические эффекты тела (заглушка без работы с хранилищем не проходит) и связи. Без неё пустой или неполный ответ прошёл бы проверку. `run.py --validate` подтверждает, что эталон каждой задачи проходит, а контекст без решения — нет.

## 3. Процедура

1. Для каждой задачи, плеча и повтора `r ∈ {1, 2, 3}` — отдельный диалог. Вызов — `claude -p --model claude-sonnet-5-5 --effort medium --tools ""` со своим системным промптом, без настроек, MCP и динамических разделов, в пустом рабочем каталоге: модель не видит репозиторий, эталоны и проверки. Раунд исправлений продолжает тот же диалог (`--resume`).
2. **Попытка 1:** промпты из `run.py`. Модель возвращает полные файлы блоками ` ```<язык> path=<путь> `.
3. **Раунды диагностик.** При неудаче модель получает первые 5 диагностик и просит исправить; не больше 2 раундов (до 3 попыток).
   - C: код, файл, строка, `data`.
   - T: строки `error TS…`.
4. Порядок «задача × плечо × повтор» перемешивается с зерном `20261023`.
5. Параметры модели: `effort: medium` (задаётся явно), рассуждение — по умолчанию CLI; параметры выборки не передаются. ID модели, effort, версия CLI и коммит фиксируются в `results/<прогон>/meta.json`.
6. Ответ без блоков файлов — неудача попытки. Файлы вне цели задачи и вне контекста не принимаются.

## 4. Метрики и порог K1

- **P1(плечо)** — доля пар «задача × повтор», прошедших с первой попытки.
- **P3(плечо)** — доля прошедших не позже второго раунда диагностик.
- **ID-поломка** (только C, задачи W13–W16, где правится файл с `@id`) — доля ответов, в которых `@id` контекста пропал или переехал на другую декларацию; переименование сохраняет ID (W15). Ответ с ID-поломкой считается непрошедшим и в P1/P3; отдельный порог ниже считает её долю.
- **Выдуманные ID** (только C) — число `@id`, которые модель написала сама. Правило SURF-07: придумывать нельзя. В порог не входит.
- **Стоимость** — входные и выходные токены по плечам.

**K1 срабатывает**, если выполняется хотя бы одно:
- `P3(C) < 0,70 × P3(T)`;
- ID-поломка C > 5 %.

Решение по K1 (план B14):
- сработал — одна ревизия синтаксиса v0.2 по разбору ошибок;
- повторный провал — bagaev становится строгим диалектом TS с эффект-аннотациями.

P1 и стоимость сообщаются рядом и на решение не влияют.

## 5. Ограничения

- Проверяется пишемость (статическая проверка и интерфейс), а не правильность поведения. Поведение проверят `bag run` и `bag test` (Ф3).
- n = 20 задач × 3 повтора. Это не статистика значимости: сообщаются доли и bootstrap-интервалы по задачам.
- Модель — одна, `claude-sonnet-5-5`. Выводы ограничены ею; для пилота Ф8 модель выбирается отдельно.
- TypeScript модель знает из обучения, bagaev — только из шпаргалки. Это и есть измеряемая асимметрия.
- TS-плечо требует `tsc`: версия TypeScript закреплена в package-lock.json.

## 6. Параметры запуска

Модель, лимит попыток и бюджет задаются явно перед запуском. Протокол сохраняет входные и выходные токены и результат каждого случая. Сохранённые результаты прошлых запусков не входят в исходный пакет.
