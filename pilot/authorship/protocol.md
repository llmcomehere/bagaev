# Черновик предрегистрации опыта A/B/C

**DRAFT · пилот NOT_RUN.** Параметры опыта ещё не заморожены. Точная версия Claude, денежный лимит и ставки полной стоимости не заданы; числовые измерения — `null`. Машиночитаемые параметры — [preregistration.json](preregistration.json). Перед запуском нужны пробник пишемости v2 и независимая проверка протокола.

## Сравнение и объём

- Только семейство **Claude**; один точный ID и одни параметры для всех вариантов, без fallback на другую модель. Выводы ограничены этим семейством.
- A — приложение TypeScript, компилятор, тесты, текстовый поиск и обычная приёмка Git CAS. B — то же приложение и общий протокол `bag op`; C — bagaev и тот же протокол. Версии, команды и исходные приложения берутся из [arms.json](arms.json), [контракта](contract.md). npm не запускается; используется уже установленный TypeScript 5.9.3.
- Предложено **5 повторений** каждого C01/C04/C05/C06/C08/C10/C11/C12 каждым вариантом: 120 задач. Нижняя граница — 3. C02/C03/C07/C09/C13 проверяет детерминированный mechanism; они не добавляются к числу LLM-попыток.
- Один блок — случай и номер повторения. Блоки и порядок A/B/C внутри блока перемешиваются с seed `20261027`. Входной seed провайдера сохраняется, но его поддержка Claude пока неизвестна. Расписание фиксируется до первого измерения, включая неисполненные строки; выборочное удаление неудач запрещено.
- Каждая задача стартует из отдельной копии. Модель не получает сообщения других попыток, reference, oracle и закрытые ожидания. Для локальных задач вроде C10 стартовое приложение уже поддерживает нескольких авторов; это общий подготовленный вход, а решение новой задачи в нём отсутствует.

Граница реализации B: после изменения снимка с тестовыми файлами нужен полный `verify` TS-runner. Граф именованных тестов не описывает весь верхний уровень их импортов; перенос `same-closure` не заменяет этот прогон ([CHG-11](../../spec/protocol/agent-protocol.md#5-свидетельства)). Дополнительные затраты входят в сравнение; результат нельзя обобщать на оптимальный анализатор TypeScript.

## Гипотезы и решения

| Гипотеза | Критерий на всём заранее закреплённом наборе |
| --- | --- |
| H1 | Ложных приёмок C ровно 0; их не больше B и A. |
| H2 | На C08/C10/C11 полная стоимость C ≤ 0,8 B при одинаковой безопасности и не меньшем числе завершений. |
| H3 | Завершённых задач C не меньше B. |

Приёмку делает сам вариант на точных входах: A — обычный Git CAS, B/C — CHANGE-1. **Скрытый оракул не является общим условием приёмки.** После окончательного решения независимый контроллер оценивает поведение, состояние и обязательные записи анализа. Принятый дефект или обязательное неизвестное — ложная приёмка. Ошибка стенда либо неприменимый oracle даёт `INCONCLUSIVE`, а не отсутствие ложной приёмки. Результаты оракула не возвращаются исполнителю до завершения всего блока.

Запущенный CLI кандидата с ненулевым exit code или невалидным JSON нарушает публичный контракт: это провал кандидата и ложная приёмка, если он был принят. Отдельная квитанция sandbox различает этот результат и невозможность запустить CLI. Таймаут либо отсутствие квитанции доверенного runner дают явный `INCONCLUSIVE`; такая неопределённость не считается подтверждением H1.

Для C04/C05/C09 успех — доказанное обнаружение подготовленного дефекта и отказ; автоматическое исправление не требуется. Для C11/C12 нужен обоснованный отказ с сохранёнными открытыми обязательствами/frontier. Для C01/C10 требуется завершённое корректное изменение; отказ от всего (`all-reject`) не подтверждает полезность и делает совместный вывод H1–H3 `INCONCLUSIVE`. Необоснованный отказ считается отдельно. `ERROR`, `INCOMPLETE`, `BUDGET_STOP`, отказы модели и остановленные попытки сохраняются в знаменателе и стоимости. Повтор после технического сбоя получает новый ID, ссылка на исходную запись остаётся; решение о повторах фиксируется до запуска.

Для H2 при нулевом B, неизвестных ставках, недостающих затратах или неравной безопасности результат `INCONCLUSIVE`. Отдельно публикуются числа завершений, ложных приёмок, необоснованных отказов и все причины остановок. Случайный успех и наблюдённый ноль не являются общей гарантией языка.

## Лимиты и полная стоимость

Черновые одинаковые лимиты попытки: 80 ходов, 24 000 токенов контекста за ход, 160 000 входных и выходных токенов суммарно, 900 секунд; один инструмент — 30 секунд. Лимиты долларов на попытку и весь опыт — `null/pending`. В dry-run нет токенов модели: длина UTF-8 используется только как консервативная верхняя оценка для проверки ограничителя, отдельно от `input_tokens/output_tokens/cost_usd = null`. Перед freeze нужен проверенный учёт реальных токенов Claude, включая output, cache и повторно отправленный контекст; эта реализация не запускает live.

Полная стоимость включает guide C, весь повторно предъявленный контекст, ответы модели, время инструментов и анализатора, подготовку связей/графа, их обслуживание, помощь человека и неудачные попытки. Подготовка распределяется поровну по 40 запланированным задачам варианта; сырые и распределённые затраты публикуются вместе. Человеко-часы и вычислительное время сохраняются отдельно; единые ставки перевода в USD фиксируются до freeze, неизвестные расходы не становятся нулём. B получает сопоставимую информацию о связях; дополнительная ручная разметка учитывается.

Основные сравнения — парные по случаям и повторениям. Bootstrap: 10 000 выборок парных блоков повторений, seed `20261028`, 95 % percentile CI для разности завершений и отношения суммарных полных стоимостей. Это описательный интервал. При **n < 10 заявлений о статистической значимости нет**; нулевое число ошибок не даёт узкого интервала риска. Способ расчёта и единица resampling закрепляются до данных.

Остановка до очередного вызова — при достижении токенов/контекста/ходов/времени/денег. Остановка процесса инструмента — с сохранением `BUDGET_STOP`; неизвестный эффект не повторяется молча. Ошибка транспорта, неподходящий вход, повреждение журнала или смена runtime — `ERROR` и сверка состояния. При ответе, не помещающемся в бюджет инструмента, возвращается `INCOMPLETE` с хешем сохранённого полного ответа; он не считается полностью прочитанным агентом.

## Изоляция, воспроизведение и hooks

[Харнесс](../harness/README.md) предоставляет `list/read/search/write/check/test/accept/resume`; B/C также `bag`. Shell, произвольные процессы и доступ к корню репозитория агенту не выдаются. Каждый исполняемый инструмент запускается через Linux `bwrap` без сети, с копией приложения и доверенным runtime, без reference, oracle, секретов и домашних каталогов. При недоступном sandbox — отказ без небезопасного fallback. Изменение файлов через посредника проверяет путь, symlink и прежний SHA-256. `guide-llm.md` неизменяем и учитывается в контексте.

Полный manifest входов, dirty revision, версии Python/Node/TypeScript/Git/bwrap, запросы, ответы, контекст каждого хода, длительность, исходники кандидата и квитанция приёмки сохраняются в каталоге прогона. Журнал JSONL связан SHA-256; это проверка повреждений, не криптографическая подпись. Checkpoint проверяется против журнала, исходников и runtime; неоднозначное продолжение требует сверки и не исполняет запись заново.

| Hook | Исполнимый dry-run и предел доказательства |
| --- | --- |
| C04/C05/C09 | Общий `oracle/mutants.py inject` меняет точный подготовленный вход, сохраняет before/after SHA-256, компилятор проверяет результат. Семантическое обнаружение подтверждает mechanism/oracle; факт правки не выдаётся за обнаружение. Произвольный несовпадающий кандидат — ошибка setup. |
| C06 | Реальный SIGKILL отдельного scripted provider; новый процесс и пустая история разговора, сохранённый checkpoint, равное состояние открытых O04/O05. Для A это явный чеклист, для B/C — контракт и отказ `OPEN_OBLIGATIONS`. |
| C07 | Реальный сдвиг head в локальном Git A либо ProjectStore B/C; старая приёмка даёт `STALE_BASE`, новый head сохраняется. Инъекция внешнего head не доказывает корректность внешнего изменения. |
| C12 | Экспорт физически убирается из видимого дерева; поиск и чтение его не возвращают. Исполнение и операции, которые могли бы раскрыть старый snapshot, отвечают `INCOMPLETE`. Это граница посредника, не новая семантика недоступных объектов движка. |

Dry-run проверяет минимум три настоящие копии A/B/C и отдельные hooks. Его scripted действия не входят в исследовательские попытки. Он сохраняет `pilot_status: NOT_RUN`, пустой список исследовательских попыток и `llm_measurements: null`. Отдельная отрицательная проба разрешает обычному A принять S0 и проверяет, что posthoc обнаруживает дефект нового задания: ложные приёмки не обнуляются конструкцией харнесса.

## Закрытые задания и commit-reveal

Автор закрытых заданий — отдельная независимая сессия. Публичная фиксация трёх закрытых C10 — [closed-commitments.json](closed-commitments.json): только ID, число задач и SHA-256 commitment; payload, nonce и решения находятся вне видимой области исполнителя. Побайтный формат commitment: SHA-256(`bagaev-pilot-hidden-task/1\0` + u64be(len(nonce)) + nonce + u64be(len(payload)) + payload). Nonce — минимум 32 случайных байта; его сохраняет автор. [commit_reveal.py](../harness/commit_reveal.py) вычисляет и проверяет хеш без копирования payload.

Исполнимый закрытый формат первой версии — **C10**: [closed.py](../harness/closed.py) проверяет reveal до подготовки копии, предъявляет только публичную инструкцию и разделитель, а независимые ожидаемые подписи использует только после завершения. Это ограниченный вариант переноса локальной правки. Закрытые C08/C11 и их записи анализа ещё требуют отдельных адаптеров и проверки; до их появления полного исследовательского набора нет.

До запуска нужны точная модель Claude, деньги и ставки, независимый пакет закрытых задач, пробник v2, проверка live-адаптера и учёта токенов, независимая проверка протокола, freeze и настройка внешнего API. Текущий `live` завершается ошибкой до запуска какого-либо провайдера.
