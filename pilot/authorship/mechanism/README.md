# Детерминированные механизмы A/B/C

`python3 pilot/authorship/mechanism/run.py` выполняет пять случаев для каждого варианта без LLM. `--arm C` ограничивает прогон одним вариантом. Данные и проектные хранилища создаются во временных каталогах; результат — JSON на stdout.

Ожидания выведены из [O01–O10 и C01–C13](../../../spec/architecture/05-authorship-experiment.md) и [CLI-контракта](../contract.md) до запуска проверяемого кода:

| Случай | Обязательное наблюдение |
| --- | --- |
| C02 | Пустой список, повтор и неизвестный человек отвергнуты; статьи, индекс и очереди прежние. |
| C03 | Соавтор без editor-права получает `PERMISSION_DENIED`; состояние прежнее. |
| C07 | Два кандидата подготовлены от одной базы и проверены. Первый принят; второй получает `STALE_BASE`. Head и число приёмок не меняются от отказа. |
| C09 | Подготовленный дефект оставляет старый индекс после доставки. Независимый оракул обнаруживает расхождение состояния/поиска; правильное решение проходит. |
| C13 | Повтор доставки завершённого события не исполняет обработчик повторно, индекс и inbox прежние. |

C02/C03/C13 используют независимые ожидания [оракула](../oracle/run.py). C09 — его отрицательный контроль с точечным [мутантом](../oracle/mutants.py). Обнаружение C09 — проверка поведения перехода, а не свидетельство способности LLM заметить ошибку и не скрытый gate принятия исходника.

C07 проверяет точный механизм на S0 приложения двумя эквивалентными правками подписи. B/C проходят реальные `change_begin → apply → verify → accept` общего CHANGE-1. A использует обычные `tsc`, `node:test` и [Git compare-and-swap](git_accept.py) над точными снимками файлов. A не получает граф или протокол B/C. Успешный кандидат — положительный контроль: отказ от всех кандидатов не проходит проверку.

`PASS 15/15` относится к этому набору механизмов. Исследовательский пилот остаётся `NOT_RUN`, число вызовов модели — 0. Недоступный Node/TypeScript даёт `INCOMPLETE` с `SKIP` соответствующих вариантов, а не успешный пустой набор. Сбой стенда — `ERROR`.
