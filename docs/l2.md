# L2 structured pure language

Contract: `bagaev-l2/1`. This specification defines L2 semantics and acceptance
obligations. A [reference evaluator](context.md#l2-library-entry) and
[local CLI and CPython backend](toolchain.md) are implemented;
[README](../README.md#what-exists-today) records bounded execution evidence and
remaining unrun checks. It preserves [L0](l0.md), [L1](l1-proposal.md)
and frozen P0. The required workload is [catalog-application/2](application.md).
JSON is the exact reference representation, not a claim about optimal syntax.

## Values and invocation

`evaluate(checked_program, argument)` either returns one detached JSON value or
raises one language error. It has no external effects, mutation, imports,
recursion, dynamic evaluation, clocks, randomness or model calls. Definitions
are reusable pure functions. Application refusals are ordinary returned records;
they are distinct from language errors caused by a defective program.

The argument domain is the APP callable domain: any finite acyclic JSON value
represented by ordinary dict/list/string/integer/finite-float/Boolean/null values,
with string object keys. Integers can be arbitrarily large on ingress. A caller
must not concurrently mutate the argument. Cycles, custom objects, nonfinite
numbers and non-string keys are outside this callable domain. No pre-call deep
validation, copying, serialization or hashing of the argument is permitted.
In particular an invalid date can contain arbitrarily deep data. Obtaining its
outer type must not visit its children. Finite does not imply a wall-clock bound.

L2 is dynamically typed. The disjoint tags are null, bool, int, float, string,
array and object; bool and float are never int. Arrays contain heterogeneous
values; object fields have string names. Missing is not a value: `has` and lazy
`if` distinguish an absent field from a present null. Tagged objects express
alternatives (such as success/refusal); ordinary records and arrays express
their payloads. There is no implicit conversion, case folding or normalization.
The checker validates syntax, bindings and call arity, not application schemas
or branch refinement. Reached primitive operands are checked as specified below.
An unreached ill-typed operation does not fail at runtime; malformed syntax in
any branch still prevents program admission.

An ingress value is a borrowed immutable reference. Navigation and scalar
predicates inspect only the specified surface. Constructors may share immutable
values internally; the successful boundary exports a fresh tree, with no mutable
container shared with the argument, the checked program or another invocation.
Export is limited as below and never starts until evaluation succeeds. Refusal
records therefore do not copy rejected input. Allocation failure is an execution
environment failure, not an application refusal or successful language result.

## Exact program and expression form

A program has exactly `schema`, `entry`, `definitions`, `pins`:

```json
{"schema":"bagaev-l2/1","entry":"main","definitions":{"main":{"params":["x"],"body":["var","x"]}},"pins":{"main":"sha256:..."}}
```

Definition and variable IDs match `[A-Za-z][A-Za-z0-9._-]{0,63}`. A definition
has exactly `params` (0..8 distinct IDs) and `body` (an expression). `entry`
names a definition with exactly one parameter. All definitions are checked,
including unreachable definitions. There are 1..64 definitions; calls must
resolve within this snapshot and the complete call graph must be acyclic.
Definitions have no caller-local scope: only their parameters and own lexical
bindings are visible. Every call's argument count must match its definition.

An expression is a null, bool, signed-64-bit int or string scalar, or one of
the arrays below. Scalar strings are literals; names require `var`. Floats
occur only in input, not program literals. Arrays are always expressions unless
inside `literal`. Objects are never bare expressions. Unknown operations,
extra operands, malformed operand metadata and unbound variables are errors.

| Expression | Meaning |
| --- | --- |
| `["literal", value]` | Bounded JSON constant, without floats. |
| `["var", name]` | Lexically bound value. |
| `["call", name, arg, ...]` | Evaluate arguments left to right, invoke pinned definition. |
| `["let", [[name, expr], ...], body]` | 1..32 sequential bindings, then body; each binding sees earlier ones, not itself. No shadowing an in-scope name. |
| `["if", condition, yes, no]` | Require bool; evaluate exactly one arm. |
| `["and", expr, ...]`, `["or", expr, ...]` | 1..32 operands, bool only; left-to-right short circuit. |
| `["not", expr]` | Boolean negation. |
| `["object", {key: expr, ...}]` | Construct record; evaluate fields in ascending Unicode code-point key order. |
| `["set", object, {key: expr, ...}]` | Evaluate object then fields in that order; shallow new record with supplied fields replaced/added, all others retained. |
| `["array", expr, ...]` | Construct array, left to right. |
| `["get", object, key]` | Require object and present literal string key; return field without visiting its contents. |
| `["has", value, key]` | True exactly for object with that literal string key; no child visit. |
| `["null", value]` | True exactly for null. |
| `["shape", value, required, optional]` | Total shallow predicate: object has every required key and no key outside these two literal arrays. |
| `["int.range", value, lo, hi]` | Total predicate: outer tag int and `lo <= value <= hi`; literal signed-64-bit endpoints, `lo <= hi`. |
| `["text", value, lo, hi, first, rest]` | Total string predicate described below. |
| `["array.bound", value, maximum]` | Total predicate: array of length 0..maximum, without inspecting elements; literal maximum 0..256. |
| `["eq", left, right]` | Scalar-only exact equality: same scalar tag and equal value; false for either container. No deep equality. |
| `["lt", left, right]` | Same-tag signed-64-bit ints or strings of at most 4096 UTF-8 bytes; numeric or Unicode code-point ascending comparison. |
| `["length", array]` | Length of an array of at most 256 elements. |
| `["map", array, name, body]` | Evaluate bounded array once; body once per element in input order in a lexical scope extended with name. |
| `["all", array, name, body]`, `["any", array, name, body]` | Same binding rule, bool bodies, short circuit in input order; empty gives true/false respectively. |
| `["unique", array]` | Array of at most 256 bounded strings; first occurrence of each exact string. |
| `["sort", array]` | Array of at most 256 bounded strings; ascending Unicode code-point order, duplicates retained. |
| `["increasing", array]` | Array of at most 256 bounded strings; true iff every adjacent pair is strictly increasing. |
| `["sort.by", array, name, key]` | Evaluate one key per element in input order, then stable ascending lexicographic order of keys; return original elements in that order. |

`required` and `optional` are disjoint literal arrays of distinct strings, with
at most 32 keys total. Shape first compares object length, then key membership;
it never follows field values. `text` has literal integer `0 <= lo <= hi <= 4096`
and `first`/`rest` each a nonempty array of at most 16 disjoint, ascending ASCII
code-point intervals `[low, high]` in 0..127. It is false for non-strings,
length outside lo..hi or any disallowed character. Character zero uses first;
all others use rest. Empty strings pass exactly when lo is zero. It checks length
before characters, and at most hi characters, without encoding a whole rejected
string. These parameters express the application's grammar rather than embed it
in the runtime. There is no host regex language.

`map`, `all`, `any` and `sort.by` require arrays of at most 256 elements and
a fresh binder ID. `sort.by` keys are arrays of 1..8 scalars; every key has the
same length and the same type in each column, each column int or string with
the `lt` bounds. Empty input has no key-type requirement. Keys are evaluated
once, not during comparisons. A non-bool condition/body or a wrong operand tag
is `L2_TYPE`; wrong key lengths are `L2_BOUNDS`. Exporting a float or a string
with an isolated surrogate is `L2_TYPE`. A missing get field is `L2_FIELD`.
Reached string operands of `lt`, elements of `unique`/`sort`/`increasing`, and
string columns of `sort.by` keys must contain only Unicode scalar values and
be at most 4096 UTF-8 bytes. An isolated surrogate gives `L2_TYPE`, even when
the operation returns only a Boolean or the string is not ultimately exported.
For `lt`, check both operand tags, then both strings' Unicode validity, then
their byte bounds, left to right within each pass. For the three string-array
operations, check the outer array tag and length first, then all element tags,
then all strings' Unicode validity, then all byte bounds, in input order within
each pass. Thus a surrogate takes precedence over an overlong string in the
same operand validation. For `sort.by`, evaluate and validate each key before
evaluating the next: after its array tag and key-length checks, check all column
tags (including agreement with earlier keys), then all string columns' Unicode
validity, then all integer/string bounds, in column order within each pass.
These checks inspect only reached bounded-string operands. `text`, `shape`,
`has`, `int.range`, `array.bound`, `null` and `eq` retain their stated shallow
rules; they do not encode or recursively validate a rejected input. In particular,
`text` returns false for a surrogate character and an invalid APP date remains
available for a shallow gate-2 refusal.
Shallow predicates and `eq`
never reject a value merely because a nested value is large or malformed.
`set` requires an object with at most 32 fields and a result with at most 32;
it does not inspect retained field values. Object construction has at most 32
fields. Every list-producing primitive is limited to 256 elements.

All operands other than metadata and the explicitly lazy forms are evaluated
left to right before the primitive checks its operands. Literal names, field
keys, bounds, ranges, shape-key arrays and binding arrays are metadata, not
expressions. `literal` data is never traversed for operation names or calls.

## Bounds, deterministic errors and identity

Program/patch JSON text uses UTF-8, has no BOM or duplicate keys and is at most
1048576 bytes. Program data has JSON nesting depth at most 128 (root depth 1),
at most 8192 expression occurrences across all bodies and expression depth at
most 64 (root expression depth 1). Literal JSON values, and exported results,
have depth at most 64, at most 65536 value occurrences, object width at most 32,
array length at most 256, string/key length at most 4096 UTF-8 bytes, signed
64-bit ints, no floats, and canonical size at most 1048576 bytes. Every occurrence
counts separately even if internal storage shares it. Literal program metadata
strings have the same byte bound. Program collection metadata has only its
explicit bounds, not the runtime object-width limit.

At runtime the maximum active definition-call depth is 64 (entry depth 1).
A run has 100000 steps: entering any evaluated expression costs one; `unique`,
`sort`, `increasing` and `sort.by` additionally cost n*n for an input of length n,
charged after operand validation but before traversal/key evaluation. Other
primitives add no steps; evaluated loop bodies and calls count normally. The
first step beyond the limit fails before its expression/primitive work. This
is a deterministic semantic work limit, not measured CPU or memory consumption.
Any reached width, length, int/string operand, call-depth, step or export bound
failure gives `L2_BOUNDS`, with no partial result. Borrowed ingress is not subject
to export bounds until it is actually exported; predicates do not export it.

Check phases, in priority order:

1. `L2_JSON`: invalid text/UTF-8/duplicate keys. Oversize text gives `L2_BOUNDS`
   before parsing. The value API skips text parsing.
2. `L2_PROGRAM`: invalid envelope, schema, metadata, definition shape, IDs,
   duplicate binding, expression arity/form, forbidden literal or unknown op.
   Structural depth/count/size bounds give `L2_BOUNDS` before further descent.
3. `L2_REFERENCE`: missing entry/callee/variable or wrong call/entry arity.
4. `L2_CYCLE`: any cycle in the complete definition-call graph.
5. `L2_PIN`: missing/extra pin key, malformed digest or digest mismatch.

Within phase 2 inspect envelope fields in the order schema, entry, definitions,
pins; definitions by sorted ID; params before body; expressions depth first in
the evaluation operand order, also inspecting both lazy arms. A bound is checked
before descending into the bounded item. For reference errors no location is
part of the conformance key. Runtime uses the specified evaluation order; check
operand tags before their size bounds. Stable error observation is exactly a
code, plus a short path-free English diagnostic whose text is not normative.
No arbitrary host exception is a language success/error result.

Let C(x) be canonical UTF-8 JSON: sorted object keys in Unicode code-point order,
no insignificant whitespace, non-ASCII characters unescaped, JSON escapes for
quote/backslash/control characters (`\b`, `\t`, `\n`, `\f`, `\r`, otherwise
lowercase `\u00xx`), integers in minimal decimal, lowercase booleans/null and
no escaping `/`. All strings must contain Unicode scalar values, not isolated
surrogates. No Unicode normalization occurs. Array order is preserved.
Let H(x) = `sha256:` plus lowercase SHA-256 of C(x).

For each definition d, compute, in dependency order:

```
pin(d) = H({"schema":"bagaev-l2-definition/1",
            "definition": definitions[d],
            "dependencies": {callee_id: pin(callee_id), ...}})
```

Dependencies are exactly the distinct direct calls in all arms of that body.
Its own ID is not included; parameter and callee names are included. The program's
pins must equal this complete computed map. A checked snapshot owns detached
immutable definitions and pins; it must not trust later mutation of caller data
or a mutable compiled wrapper. There is no lookup by latest name, filesystem,
network or ambient registry. Reusing one definition requires the same transitive
pins. Changing a callee creates new caller pins even if its caller body is unchanged.
Program identity is H(the entire checked program); whitespace/object order do
not change it, but entry, unused definitions and every semantic field do.
Hash equality is content binding, not proof of correctness or authority.

## Transactional structural change

A patch has exactly `schema`, `base`, `target`, `add`, `replace`:

```json
{"schema":"bagaev-l2-patch/1","base":"sha256:...","target":"sha256:...","add":{},"replace":{}}
```

Both maps contain definition IDs and complete new definitions; their key sets
must be disjoint and at least one must be nonempty. There is no deletion,
root replacement, data migration or in-place update in this profile: none is
needed for the three catalog changes. Existing function signatures may change
only if the whole candidate remains valid. A patch is not permission to run it.

`apply_patch(original, patch)` checks the original first. Then it checks patch
text/envelope/map shapes/digest spellings (`L2_JSON`, `L2_BOUNDS`, `L2_PATCH`),
compares base with the original identity (`L2_STALE`), and verifies add IDs are
absent and replace IDs present (`L2_PATCH`). It builds a private candidate,
applies every replacement/addition together, checks its graph, recomputes the
complete pin map, and checks its resulting identity against target
(`L2_TARGET`). Candidate semantic errors use the ordinary check codes; supplied
target cannot conceal a bad definition. Success returns a detached checked new
program. Failure exposes no candidate and leaves original, patch and every
retained snapshot unchanged. There is no disk/store commit or shared mutable
transaction owner: the caller owns snapshots and chooses whether to retain
the successful return. Concurrent calls with the same original can independently
produce values; serial admission/CAS against mutable store state is future work.

## Catalog programs and acceptance

[catalog.json](../examples/l2/catalog.json) is revision A0. Three complete
structural changes, [01](../examples/l2/catalog-01.patch),
[12](../examples/l2/catalog-12.patch), [23](../examples/l2/catalog-23.patch),
produce A1, A2, A3. Each changes language definitions and its declared supported
selector ceiling, rather than routing to host implementations. Apply them to
retained snapshots, never mutate A0/A1/A2. Literal identities are in the
[oracle](../examples/l2/oracle.json).

Ak accepts selectors 0..k; higher selectors return invalid-request at gate 1.
Within those selectors it implements exactly catalog-application/2. A1 changes
tag normalization, A2 changes manual preservation and gate 7, A3 changes the
missing-date key. Earlier selectors keep their previous semantics. This is
additive behavior support, not a state schema migration. State snapshots cannot
recover lost tags/order merely by choosing an earlier selector.

The source's `valid` implements gate 1, `dated` gate 2, the distinct-ID and
increasing predicates gates 3/4, `disjoint` gate 5, existence gate 6, and
`replacement-ok` gate 7. They run in that order through lazy `if` forms. Only
then does `transform` reconstruct state; `key` constructs an explicit integer,
date, ID ordering tuple. No catalog primitive, Python delegation or fixture-ID
switch is admitted. All input bounds/grammar are literal language parameters.

A3 must run every one of the 99 immutable APP oracle cases, with exact original
request selectors and expectations. Ak must run every case whose selector is an
integer in 0..k and every malformed case (for a valid unsupported selector its
historical expected result is invalid-request). Do not rewrite the APP oracle.
The EVOLUTION chain must execute CHAIN-0 on A0, CHAIN-1 on A1, CHAIN-2 on A2,
CHAIN-3 on A3, feeding actual preceding output state into the next request;
also run that chain and REPLAY-OLDER on A3. Validate all original request
nonmutation and input/output container disjointness obligations. Check retained
older snapshots after each patch; they must retain identity and observations.

The small language oracle has literal expectations independent of evaluator
code. Expression cases use one entry definition with the shown parameter and
body, pin it by this contract, and invoke it with the literal argument; checking
cases deliberately corrupt that data as specified. This binding step is generic
data preparation, never computation of the expected output. Exact APP values
remain in the existing oracle and are not duplicated here. Boundary families
state their deterministic data construction and literal outcome where writing
hundreds of repeated values would obscure review. No evaluator, execution
profile, test result, compiler or runtime admission is supplied by these files.

L2's scope follows foundation B01–B05 (contract, identity, composition and exact
form), B07–B09 (checking, bounds and pure execution), B14–B16 (change and content
binding), and B17's rejection of unknown operations. It makes no B06/B18 model
or cost claim and supplies no B10–B13 hardware, distributed, durable-store or
agent-protocol implementation. The internal project contracts above are the
normative sources; no external standard's conformance is claimed.
