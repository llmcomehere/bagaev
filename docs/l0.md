# L0 executable language slice

L0 is a small reference language for testing executable semantics and structural
program changes. It is not evidence of optimized syntax, native compilation,
P0 conformance, model advantage, lower cost, or production readiness. JSON is
the versioned transport and reference form for this slice; no claim is made
that it is the best model-facing representation.

## Program contract

A program is a JSON object with exactly these fields:

```json
{"schema":"bagaev/l0-program/v1","nodes":[],"result":{"ref":"node-id"}}
```

`nodes` contains 1 to 256 objects. Node order has no semantic meaning. Every
node has a stable `id` matching `[A-Za-z][A-Za-z0-9._-]{0,63}`, an `op`, and
only the fields listed below. Every reference is exactly `{"ref":"node-id"}`.
The result may have any L0 type.

| Operation | Additional fields | Result |
| --- | --- | --- |
| `input` | `name`, `type` | supplied value |
| `literal` | `type`, `value` | literal value |
| `identity` | `value` reference | referenced value |
| `list.concat` | `items` with 1 to 32 references | concatenated string list |
| `list.unique` | `value` reference | first occurrence of each string |
| `list.sort` | `value` reference | ascending Unicode code-point order |
| `list.length` | `value` reference | list length as an integer |
| `int.add` | `left`, `right` references | checked integer sum |
| `int.equal` | `left`, `right` references | Boolean equality |
| `bool.not` | `value` reference | Boolean negation |

The four types are `int`, `bool`, `string`, and `string_list`. Integers are
signed 64-bit values. A string is at most 4096 UTF-8 bytes. A list contains at
most 256 strings. JSON input is at most 1048576 bytes. Boolean values are not
integers. Input names use the same grammar as node IDs and are unique.

Before evaluation, L0 rejects duplicate JSON keys and node IDs, missing or
unknown fields, unknown operations and types, invalid references, type errors,
and cycles. It then validates the complete inputs object, including exact keys
and all value bounds. Evaluation is eager, pure, and deterministic: every
admitted node is evaluated once in full topological order, including a node not
reachable from `result`. It has no loops, recursion, imports, dynamic
evaluation, FFI, filesystem or network effects, randomness, clocks, or model
calls. A checked runtime overflow or result-size violation in any node rejects
the run without exposing a partial result.

The program digest is `sha256:` followed by lowercase SHA-256 of UTF-8 JSON
with object keys lexicographically sorted, no insignificant whitespace, and
`ensure_ascii=false`. Nodes are first sorted by `id`; array order elsewhere is
preserved. Thus object-key and node ordering do not change the digest, while
every admitted semantic field does.

## Atomic structural patch

A patch has exactly `schema`, `base`, `add`, and `replace`:

```json
{"schema":"bagaev/l0-patch/v1","base":"sha256:...","add":[],"replace":[]}
```

`base` must equal the checked program digest. `replace` keeps an existing node
ID and replaces its complete definition; `add` introduces a new ID. An ID may
occur at most once across both arrays. L0 builds a private candidate, validates
the complete resulting graph, and returns it only on success. A stale base or
invalid change raises a deterministic error and leaves the original object
unchanged.

## Library and CLI

The standard-library-only module `src/bagaev_l0.py` exposes `loads_json`,
`compile_program`, `program_digest`, `run_program`, and `apply_patch`.
`L0Error.code` is stable; its short English message contains no local path.

From the repository root:

```console
python3 src/bagaev_l0.py check examples/l0/tag_list.json
python3 src/bagaev_l0.py run examples/l0/tag_list.json examples/l0/tag_inputs.json
python3 src/bagaev_l0.py patch examples/l0/tag_list.json examples/l0/tag_unique_sorted.patch
python3 src/bagaev_l0.py run examples/l0/composed.json examples/l0/composed_inputs.json
```

Each successful command prints one `bagaev/l0-result/v1` JSON object and exits
0. `check` reports digest, node count, sorted input names, and result type;
`run` adds the result; `patch` returns the complete checked replacement and its
old and new digests. A language, JSON, bound, or input-file error prints the
same schema with `ok:false`, `error.code`, and `error.message`, then exits 2.
Argument-parser errors use the conventional CLI usage output and exit 2.

The original example preserves order and duplicates. Applying the patch changes
the graph to `list.sort(list.unique(tags))`. The composed example concatenates
a literal list, removes duplicates, takes its length, and adds an integer; it
exists to demonstrate composition beyond the tag fixture.
