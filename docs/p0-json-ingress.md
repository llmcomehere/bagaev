# Bounded P0 JSON request ingress

This supplemental slice implements the malformed-envelope boundary stated in
[frozen P0](p0.md), without changing its oracle or receiver ordering. It accepts
only raw UTF-8 JSON write and transfer envelopes. Initial state, sessions and
grants remain trusted synthetic fixtures. Admission, handoff and scenario-event
records are not made general untrusted-input APIs by this adapter.

The selected transport profile is `p0-json-ingress/1`: bytes only, at most
65,536 bytes and 64 nested JSON containers. Duplicate object keys are not
admitted because they give an ambiguous envelope. These transport refusals are
distinct from P0 `invalid-request`; they are not new frozen semantic outcomes.
No network, file I/O, candidate execution, actual concurrency or crash durability
is implemented. A malformed scenario fixture is still invalid test data.

For admitted bytes, malformed JSON/UTF-8, non-finite JSON constants, a non-object
envelope, missing/extra envelope fields, wrong structural values and noncanonical
sets produce `request-refusal` / `invalid-request` without dispatching a receiver
command or changing state/receipts. Writes require exactly session,
presented_epoch and intent; transfers require exactly session and intent.
The existing receiver owns structural intent definitions and all ordered current
authority, receipt and contract checks. Invalid tag grammar is deliberately left
to its ordered committed-contract-refusal gate; it is not a parse error.

After successful decoding, invoke the original receiver exactly once. An exact
retry retains the original receipt. Refusal observation reads a detached model
snapshot only. The API selector is supplied by the trusted caller, not inferred
from a request field; unsupported selectors are programmer errors.

## Supplemental expectations frozen before implementation

The separate fixture selection pins the unchanged contract and oracle. Use a
fresh protocol-base per independent case. Expected observations are literals or
the existing frozen receipt fixture, never results generated by the adapter.

- Correct write and transfer match their frozen receipts; write retry does not
  change the committed state or create a second receipt.
- Truncated JSON, invalid UTF-8, non-object JSON, missing envelope/intent fields,
  extra envelope fields, non-string session, Boolean/overflow revisions,
  noncanonical/duplicate sets and non-finite constants refuse before dispatch.
- Invalid tag with current authority commits invalid-tag refusal; stale epoch
  wins first and creates no receipt. This preserves semantic ordering.
- Duplicate keys, non-byte input, byte overflow and depth overflow are transport
  refusals, with zero receiver calls. Exactly the byte/depth bounds remain admitted.
- Every pre-dispatch refusal leaves the complete before/after state identical;
  returned observations and caller request bytes cannot mutate model state.

Execution status is recorded separately. Source existence is not test evidence.
