# Checked CPython artifacts for authored records

The standalone compiler accepts readable record-form/5 sources and the bounded
typed-record/11 operation subset used by the catalogue application. It calls an
explicit hash-pinned source checker and emits a deterministic data artifact.
It does not run the generated Python or grant execution admission.

Use a trusted, separately reviewed source checkout and checker under your
approved bounded execution profile. A fresh CPython process with bytecode writes
disabled and assertions enabled is required; qualification used CPython3.12.14.
No package download is needed. The compiler uses only Python's standard library.

```
python -B -S tools/record_cpython_compile.py --help
python -B -S tools/record_cpython_compile.py examples/probes/cpython/constant.bagaev \
  --source-sha256 SOURCE_SHA256 --checker /absolute/path/to/record-check \
  --checker-sha256 CHECKER_SHA256 --output /new/output/directory
```

Replace the placeholders with verified hashes of your exact authorized inputs.
An existing output directory is refused. Successful output has six files:
source.bagaev, program.json, checker.stdout, checker.stderr, artifact.json and
receipt.json. Stdout is the canonical receipt followed by one newline. The
artifact holds Python text and program/generator/runtime hashes. Generated code
is specialized to the checked program; it uses an explicit iterative scheduler,
shared bounded work accounting, lazy branches and bounded value operations.

Usage errors return2 with CPY_USAGE. Compile refusals return1 with an exact
CPY_* code, including CPY_PIN, CPY_PROFILE, CPY_CHECK_REFUSED, CPY_UNSUPPORTED,
CPY_OUTPUT and CPY_CHECKER. Partial output is retained on failure and is not a
successful receipt. A receipt-delivery failure is CPY_DELIVERY; do not interpret
successful retained files as successful stdout delivery or retry implicitly.

The internal compile_flow API returns a current-process immutable checked
handle. verify_artifact compares incoming bytes against regenerated bytes from
that handle and the still-loaded trusted source closure. It returns verified
Python bytes, without executing them. A saved receipt cannot reconstruct the
handle; another process must perform a fresh authorized check. These controls
are not authentication against hostile Python reflection or filesystem races.
Do not execute arbitrary downloaded artifacts because their metadata looks valid.

Unsupported operations are refused even in an unselected branch. This is not a
backend for every typed-record operation or profile12. Limits include Int64,
65536 work units, bounded text/lists and a1MiB conceptual invocation frame.
JSON integer spellings are retained without floating-point coercion. Preparation
refusals are distinct from language-result wires.

Portable CLI checks (four actual checker calls, no generated execution):

```
python -B -S tests/probes/cpython_compile_process_checks.py \
  --checker /absolute/path/to/record-check --checker-sha256 CHECKER_SHA256 \
  --output /external/fresh/test/output
```

The checks cover help/usage, two deterministic compiles, wrong pins, existing
output, broken receipt delivery and a real type refusal, preserving source and output membership. Broader
selected-workload execution qualification is separate from these CLI checks.
Neither selected tests nor receipt consistency establish universal equivalence,
performance improvement, model benefit, independent admission or functional CI
coverage. Existing LLVM compilation routes are unaffected. This public slice
provides a standalone command; integration with additional authored-record
commands is a separate dependency.
