# A typed change with CPython and a fresh reader

This is a bounded companion to the [typed reference journey](typed-journey.md).
It uses the same one-function per-SKU change and the original `cross10` literal
case: five units each of a and b, both starting at twenty. The complete expected
result commits both reservations, leaves both stocks at fifteen, and includes
both receipt snapshots. The expectation is not generated by executing the code.

The [authored CLI](record-cli.md) supplies each stage. No new executor, store,
receiver or language operation is introduced. One command runs in each fresh
Python process. Do not import a reader and then run a compiler in that process.

## Before starting

Use a trusted checkout containing these tools and fixtures, Python 3, and your
separately reviewed checker. The example needs an authorized bounded offline
execution profile. `-B -S` and hashes alone do not provide one. Keep assertions
enabled; unset `PYTHONPATH` and `PYTHONHOME`. Nothing here installs a dependency,
downloads a checker, requests provider access or grants execution permission.

The source, change and emitted-Python identities below refer to the reviewed
candidate. If your compiler/runtime version emits different Python, stop and
review the new text before supplying a new expected hash. Do not substitute an
artifact's own reported hash merely to make execution pass.

Set `CHECKER` to an absolute path and `CHECKER_SHA` to its independently established
identity. Choose a new output directory with trusted ancestors. Run the following
from the repository root; the output directory must not be inside `src` or `tools`.

## Change and retain the source

These five commands prepare data and source history. They do not execute the
application. Context includes the selected function's source body; replacement
creates a draft, and export applies that draft to a new source file.

```sh
"$PY" -B -S "$ROOT/tools/record.py" function context "$SOURCE" --form 5 --name batch_apply --source-body --output "$OUT/context.json"
"$PY" -B -S "$ROOT/tools/record.py" function replace "$SOURCE" --form 5 --replacement "$FRAGMENT" --base "$BASE" --function-pin "$FUNCTION" --output "$OUT/draft.json"
"$PY" -B -S "$ROOT/tools/record.py" export "$SOURCE" --form 5 --draft "$OUT/draft.json" --base "$BASE" --target "$TARGET" --preserve-layout --source-sha256 "$SOURCE_SHA" --replacement-source "$FRAGMENT" --output "$OUT/PerSku.bagaev"
printf '%s  %s\n' "$CHANGED_SHA" "$OUT/PerSku.bagaev" | sha256sum -c -
"$PY" -B -S "$ROOT/tools/record.py" history init "$SOURCE" --form 5 --source-sha256 "$SOURCE_SHA" --program-sha256 "$BASE" --output "$OUT/initial-history.json"
"$PY" -B -S "$ROOT/tools/record.py" history append "$OUT/initial-history.json" --form 5 --package-sha256 741195949aed4d3c414a16041ae07c793a8947a4d2810c381fefe864fcadd3d7 --head df21665e403f175d55fedbc6520dbcba69ed9a8b0357859e37d20e42acee21c0 --source "$OUT/PerSku.bagaev" --source-sha256 "$CHANGED_SHA" --program-sha256 "$TARGET" --output "$OUT/history.json"
```

## One explicitly authorized application run

The next command invokes the checker, compiles from source, and compares the
emitted Python with the caller-reviewed pin before evaluation. It does not run
saved artifact input. See the [source-run boundary](record-cpython-run.md).

```sh
"$PY" -B -S "$ROOT/tools/record.py" run-cpython "$OUT/PerSku.bagaev" --source-sha256 "$CHANGED_SHA" --arguments "$ARGS" --arguments-sha256 "$ARGS_SHA" --checker "$CHECKER" --checker-sha256 "$CHECKER_SHA" --python-sha256 "$PYTHON_SHA" --output "$OUT/run"
RECEIPT_SHA=$(sha256sum "$OUT/run/receipt.json" | cut -d' ' -f1)
(set -C; printf '%s\n' "$RECEIPT_SHA" > "$OUT/receipt.sha256")
"$PY" -B -S "$ROOT/tools/record.py" verify-cpython-run "$OUT/run" --receipt-sha256 "$RECEIPT_SHA" --source-sha256 "$CHANGED_SHA" --program-sha256 "$TARGET" --arguments-sha256 "$ARGS_SHA" --runner-sha256 "$RUNNER_SHA" --output "$OUT/verified.json"
"$PY" -B -S "$ROOT/tools/record.py" verify-cpython-run-expectation "$OUT/run" --receipt-sha256 "$RECEIPT_SHA" --source-sha256 "$CHANGED_SHA" --program-sha256 "$TARGET" --arguments-sha256 "$ARGS_SHA" --runner-sha256 "$RUNNER_SHA" --expectations "$EXPECTED" --expectation-sha256 "$EXPECTED_SHA" --case cross10 --output "$OUT/compared.json"
```

Inspect `verified.json` for `consistent` and `compared.json` for `matched`.
Comparison also returns zero for `mismatched`, so exit zero alone is insufficient.
Neither report authenticates a producer or grants permission for another run.
Preserve the receipt identity independently across the handoff. A pin file stored
beside a bundle is convenient, but rewriting both is not prevented by these tools.

## Continue in a fresh process without running again

Start a new terminal process. Restore the root/output paths and the literal pins
above from your retained record, not from an arbitrary replacement bundle.
Checkout requires no application execution. Verify the history's expected bytes
before checkout, and the checked-out source afterward.


Missing or partial receipts do not prove that execution never started. Retained
partial output and failed stdout delivery require reconciliation, not automatic
rerunning. Reports require trusted ancestors and can remain partial on failure.
See the [reader limitations](record-cpython-retained.md).

This composition does not establish model usefulness, independent reproduction,
performance or general correctness. The broader twelve-case business evidence,
presence cases and reader tamper controls keep their original scope; this short
recipe does not repeat or expand them. The shell text describes the public CLI
sequence, rather than supplying an execution sandbox or a claim of verbatim
