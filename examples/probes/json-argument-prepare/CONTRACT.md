# Lossless explicit Json-entry invocation preparation
Existing record_text.prepare accepts Int64-only JSON numbers; preserve it unchanged. Add separate data-only record_json_prepare for explicitly selected form4/profile10 or form5/profile11 with an existing entry whose parameters are all Json (zero args allowed). Source is parsed by existing codec, arguments must be one complete UTF8 JSON array of exact arity, no duplicate object keys, unpaired surrogates, NaN/Infinity, trailing content or depth>128. Argument numeric lexemes are never converted or rounded: validation uses opaque markers, emitted invocation retains original argument bytes exactly. Depth and1MiB input/final-frame bounds retained; exclusive output path via existing transport. Entry signature/count failure before output. No semantic execution/admission, filesystem race guarantee, compiler/runtime/permission/workflow change. General JSON numbers only in this explicit Json argument route, not source literals or typed arguments.
