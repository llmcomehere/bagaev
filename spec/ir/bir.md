# BIR-1 — единое промежуточное представление

**r30 · WORKING_DESIGN (D77).** BIR-1 — единственный IR bagaev: в него понижается проверенная программа, его исполняет [MACHINE-1](../runtime/machine.md), по нему строится граф связей (Ф5). Прежние исследовательские представления [typed-core.md](typed-core.md) и [data-forms.md](data-forms.md) — профиль исследования, заменённый этим документом. Правила имеют идентификаторы `BIR-nn`.

## 1. Модуль и функции

**BIR-01.** Проверенный проект понижается в набор групп функций. Все `fn`, точки входа и тесты модуля образуют одну рекурсивную группу (`LetRec` модуля, SURF-09, D74). Группа связывается до запуска и не тратит шагов машины (MACHINE-1 §3). Функция — `(qname, арность, тело)`.

**BIR-02.** Типы стираются (D75). Узел хранит только то, что нужно для исполнения. Статический тип значения нужен лишь для наблюдения (CANON-11) и берётся из проверки.

**BIR-03.** Каждый узел имеет `nid` и место в исходнике `(файл, start, end)`. Синтезированный узел (развёртка `?`, `and`, обновления записи) получает место своей исходной конструкции. `nid` уникален в программе; его формат — дело реализации, в наблюдения conformance он не входит.

## 2. Формы

**BIR-04. Локальные имена** разрешены в индексы: `Local(i)` — i-е связывание от ближайшего, 0 — последнее. Связывания создают:
- `Let` — одно;
- `Lambda` и вход в тело функции — по одному на параметр, в порядке параметров (последний параметр — индекс 0);
- ветвь `Match` с переменной нагрузки — одно;
- ветвь без переменной (`_` или без скобок) — ни одного.

| Форма | Поля | Источник |
| --- | --- | --- |
| `Const` | значение | литерал; `()`; вариант без нагрузки; `-N` с литералом N (SURF-35) |
| `Local` | индекс | параметр, `let`, переменная ветви |
| `Global` | функция группы | имя функции модуля |
| `Let` | значение, тело | `let x = e;` и оператор `e;` (связывание без имени) |
| `Lambda` | арность, тело | `fn(x, …) => e`; функция std-примитива или вариант с нагрузкой как значение |
| `Call` | функция, аргументы | вызов функции модуля или значения fn-типа |
| `If` | условие, ветви | `if`; `a and b` = `If(a, b, false)`; `a or b` = `If(a, true, b)` (SURF-33); `if` без `else` — ветвь `()` |
| `Match` | разбираемое значение, ветви по тегу | `match`; `e?` (SURF-39) |
| `Variant` | тег, ordinal, нагрузка | вариант с нагрузкой; конструктор opaque (ordinal −1: значение — само представление) |
| `Record` | (слот поля, выражение) в исходном порядке, число полей | литерал записи, `emit` |
| `Field` | значение, слот | `r.f` |
| `SeqLit` | элементы | `[…]` |
| `MapBuild` | ключи и значения пар подряд | `Map {…}` (SURF-30) |
| `Prim` | имя `x.y@ревизия`, аргументы | функции std с телом `{}`; операторы |
| `Return` | значение | `return`; ветвь ошибки `?` |
| `Perform` | операция, ресурс, аргументы | функции `std.store`, `emit` (EFF-01) |

**BIR-05. Блок** `{ s1; …; sn; t }` — цепочка `Let`; без хвоста — `Const(())` в конце (SURF-23).

**BIR-06. Обновление записи** `T { ..b, f: e }` — `Let($base = b, Record(явные поля в исходном порядке, затем Field($base, слот) для остальных))` (SURF-27).

**BIR-07. `e?`** — `Match(e, Ok(x) => x, Err(y) => Return(Err(y)))`. Для Option — `Some(x) => x, None => Return(None)` (SURF-39).

**BIR-08. Операторы** — примитивы `op.<имя>@1`:
- `add sub mul div rem neg` — с ловушкой (D72);
- `not`, `eq ne` — на Eq;
- `lt le gt ge` — на Key;
- `concat_string concat_bytes concat_seq` — по статическому типу операндов `++`.

**BIR-09. Функции std.** Функция модуля `std.*` с телом `{}` — примитив `std.<модуль>.<имя>@1`; её вызов — `Prim`, а для `std.store` — `Perform`. Остальные функции std написаны на bagaev (`seq.map`, `seq.fold`, `option.map`, `result.map`, `result.map_error`) и понижаются как обычный код (CHK-04).

## 3. Каноническая форма

**BIR-10.** Сериализация BIR-1 для хеша и сравнения реализаций — BAG-CJSON-1, дайджест `digest("bir-module", "1", …)` (CANON-08). Схема и равенство канонических BIR двух реализаций (ворота паритета G2) — Ф9.
