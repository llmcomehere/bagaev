# KERNEL-CANON-1 — канонический JSON, ссылки и представление значений

**r26 · контракт V1 (D78).** До r26 этот предмет был определён пять раз с расхождениями (ledger CL-104, CL-105). Здесь он задан один раз.

Документ применяется ко всему, что хешируется или сравнивается побайтно:
- канонический BIR;
- значения в отчётах `bag run` и в поле `value` наблюдений (CANON-11); сами наблюдения conformance — обычный JSON ([conformance/README.md](../../conformance/README.md));
- receipts, записи приёмки, рёбра графа;
- метаданные выпуска.

Обычные файлы репозитория, например `case.json` или реестры, — просто JSON: читаются любым корректным парсером и не канонизируются.

Правила имеют идентификаторы `CANON-nn`.

## 1. BAG-CJSON-1

**CANON-01. Кодирование.** UTF-8 без BOM, строгий: [lexical.md](../language/lexical.md) LEX-01. Документ — ровно одно значение JSON без завершающего перевода строки.

**CANON-02. Значения.**
- Допустимы объекты, массивы, строки, `true`, `false`, `null`.
- **Чисел JSON нет.** Целое записывается строкой: десятичная запись без `+`, без ведущих нулей, `-0` запрещён. Допустимый диапазон задаёт схема поля (CANON-07).
- Числа с плавающей точкой, NaN и Infinity недопустимы ни в каком виде.

**CANON-03. Объекты.**
- Имена уникальны: повтор → отказ декодера, а не «последний выигрывает».
- Имена сортируются по последовательности Unicode scalar values. Это не порядок UTF-16 из RFC 8785 и не порядок байтов локали.

**CANON-04. Строки.**
- Кавычка и обратная косая черта экранируются `\"` и `\\`.
- U+0000–U+001F записываются **всегда** как `\u00xx`, строчными шестнадцатеричными цифрами. Коротких форм `\n` и `\t` нет.
- Все остальные scalar values пишутся буквально.
- Суррогаты (в том числе экранированные) запрещены. Нормализации Unicode нет.

**CANON-05. Пробелы.** Между токенами пробелов нет.

**CANON-06. Проверка.** Декодер канонической формы:
1. разбирает документ;
2. кодирует его обратно по CANON-01…05;
3. сравнивает байты.

Несовпадение → отказ `NON_CANONICAL_JSON`. Внешнее представление не исправляется молча.

## 2. Числа, счётчики, хеши

**CANON-07. Общие типы полей:**

| Тип | Запись | Диапазон |
| --- | --- | --- |
| `Counter` (StateVersion, ревизии, поколения, epoch) | десятичная строка | 0 … 2^63 − 1; сложение проверяет верхнюю границу до записи; переполнение — отказ, а не wrap |
| `Int64` (значение языка) | десятичная строка | −2^63 … 2^63 − 1 |
| `Size` (байты, длины) | десятичная строка | 0 … 2^63 − 1 |
| `Sha256` | 64 строчных hex-символа | — |
| `Id` | ASCII `[A-Za-z0-9][A-Za-z0-9._-]{0,127}` | — |
| `EntityId` | `@id` исходника, 6 символов Crockford base32 (SURF-07) | — |

**CANON-08. Дайджест с разделением доменов:**

```text
digest(kind, version, body) = SHA-256( UTF8("bagaev/" + kind + "/" + version) || 0x0A || BAG-CJSON-1(body) )
```

- Запись — `Sha256` (CANON-07).
- `kind` и `version` — ASCII `[a-z0-9-]+`, например `digest("bir-module", "1", …)`.
- Тело никогда не содержит собственного дайджеста. Объект ссылается только на ранее созданные объекты, поэтому граф хешей ацикличен по построению. Это одно правило заменяет отдельные доказательства ацикличности в R17–R23.

## 3. Ссылки

**CANON-09. ObjectRef** — ссылка на неизменяемые байты:

```json
{"format":"bag-cjson-1","kind":"bir-module","sha256":"…","size":"1532"}
```

- `kind` — вид объекта; `format` — формат байтов вместе с кодеком.
- `sha256` — SHA-256 **ровно хранимых байтов**; `size` — их длина.
- Одинаковый `sha256` при другом `kind` не разрешает подстановку.
- Расположение, URL и имя файла в идентичность не входят.

**CANON-10. KeyRef** — ключ идемпотентности:

```json
{"key":"set-authors-a101-0007","namespace":"blog.editor"}
```

- `namespace` — `Id`; `key` — 16…128 символов `[A-Za-z0-9_-]` (ядро R16).
- Повтор того же ключа с другим запросом → `IDEMPOTENCY_CONFLICT`.
- В V1 ключи не истекают и поколений нет (план §B12). Поэтому прежние поля `project_id` и `generation` из R16 в V1 не используются.

## 4. Наблюдаемое значение

**CANON-11. Значение языка в наблюдении** (conformance, отчёты `bag run`) — объект BAG-CJSON-1 с полем `type`:

| Тип | Запись |
| --- | --- |
| Bool | `{"type":"Bool","value":true}` |
| Int64 | `{"type":"Int64","value":"-5"}` |
| String | `{"type":"String","value":"текст"}` |
| Bytes | `{"type":"Bytes","hex":"00ff"}` — строчные hex-цифры |
| Unit | `{"type":"Unit"}` |
| Record T | `{"type":"<T>","fields":{"имя":<значение>,…}}` |
| Вариант суммы T | `{"type":"<T>","tag":"Имя","payload":<значение>}`; без данных — без `payload` |
| Seq<T> | `{"type":"Seq<T>","items":[…]}` |
| Map<K,V> | `{"type":"Map<K,V>","entries":[[<ключ>,<значение>],…]}` в порядке Key |
| Opaque T | `{"type":"<T>","value":<значение представления>}` |
| Fn | `{"type":"Fn"}` — значение функции не наблюдается |

`<T>` — каноническое написание типа:
- пользовательские типы квалифицируются модулем: `blog.authorship.Authors`;
- аргументы через `,` без пробелов: `Result<Int64,std.i64.ArithmeticError>`;
- предопределённые — без модуля;
- функциональный тип пишется `Fn` и внутри аргументов: `Seq<Option<Fn>>` (r30).

Option и Result — суммы с тегами `None`/`Some`, `Ok`/`Err`.

## 5. Прежние профили и их судьба

| Профиль (где) | Отличие от BAG-CJSON-1 | Решение |
| --- | --- | --- |
| CJ-INT-1 ([idempotency-lifecycle.md](../protocol/idempotency-lifecycle.md) §2) | короткие экранирования `\b \f \n \r \t`; `page_size` числом | экранирования и числа — по CANON-02/04 при встраивании R16 (Ф4, Ф6) |
| RecoveryJSON-1 ([recovery-set.md](../distribution/recovery-set.md)) | счётчики u64 | заморожен (D88); при возобновлении — CANON-07 |
| BAG-META-JSON-1 ([dependency-lock.md](../toolchain/dependency-lock.md)) | только ASCII-ключи, сортировка ASCII; размеры u64 | для ASCII-ключей порядок совпадает; диапазоны — CANON-07 |
| FRAME-BODY-0.1 ([wire-abi.md](../ffi/wire-abi.md)) | только ASCII-ключи | заморожен (D87/D88) |
| JSON метаданных CODEC-0.1 ([value-codec.md](../data/value-codec.md)) | настройки библиотеки Python; числа | BD07 отложен (план, Ф3); метаданные — BAG-CJSON-1 |
| ObjectRef R17–R23 | поле `codec`, `bytes` вместо `size`, у R22/R23 числом | CANON-09 |
| KeyRef R16/R20/R24 | разные формы `generation` и `key` | CANON-10 |

Байты замороженных моделей и тегов не меняются: их дайджесты остаются в своих исторических профилях. Новые артефакты используют только BAG-CJSON-1.
