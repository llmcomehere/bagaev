# 05. Первый опыт: один автор → несколько

**Статус: проект опыта T15; программа и измерения не запускались.** Файл [authorship-fixtures.json](../../registry/data/core/authorship-fixtures.json) содержит реальные примеры входных данных и заранее выбранных ожидаемых результатов. Это иллюстративные фикстуры, а не результаты работающего bagaev и не утверждённый формат его runtime.

Опыт проверяет [foundation](../foundation.md), [модель программы](01-program-model.md), [ограниченный профиль](02-language-runtime.md) и [алгоритмы изменения](03-change-algorithms.md). Порядок подготовки определён в [ROADMAP](../../registry/PLAN.md). Полная IDE и native-компилятор для начала не требуются: достаточно интерпретатора, операций изменения, графа и воспроизводимого протокола.

## 1. Точная задача и исходная программа

Задача — **авторская атрибуция статьи**. Совместное редактирование документа не входит в изменение. Список соавторов и список имеющих право редактировать — самостоятельные данные с самостоятельными контрактами.

В исходном проекте есть статьи, люди, редактор авторства, подпись под статьёй, профиль автора, поиск, экспорт и обработка изображений. Поиск читает сохранённый индекс. Индекс обновляет отдельный обработчик события `ArticleAuthorshipChanged`, поэтому зависимость через событие присутствует в конструкции опыта, а не только в его описании.

Статья `a_101` «Типы и связи» первоначально принадлежит Алине Петровой (`p_alina`), статья `a_102` «Поиск по данным» — Борису Соколову (`p_boris`). Редактор `u_editor` вправе менять авторство. Пользователь `u_boris` связан с Борисом, но права редактора не имеет.

Разрешённое изменение заменяет обязательство «ровно один автор» следующим контрактом: авторов хотя бы один, идентификаторы существуют, повторов нет, порядок сохраняется. Смысловая сущность авторства сохраняет ID, её контракт и представление получают новые ревизии. Остальные обязательства нельзя незаметно ослабить.

После миграции старые статьи содержат `[p_alina]` и `[p_boris]`. Затем редактор задаёт для `a_101` порядок `[p_boris, p_alina]`. Подпись показывает «Борис Соколов · Алина Петрова», поиск по Борису возвращает обе статьи, по Алине — `a_101`. Экспорт сохраняет обоих в указанном порядке. Событие доставки намеренно повторяется; индекс не получает дублей.

## 2. Независимый оракул обязательств

До измерения независимый проверяющий фиксирует требования, исходные данные, допустимые переходы и ожидаемые результаты. Проверяемое ядро оракула приведено в JSON. Оно не ограничивается перечнем файлов: правильное решение может организовать исходники иначе.

| ID | Обязательство |
|---|---|
| O01 | Непустой упорядоченный список существующих людей без повторов; ошибочная запись не меняет состояние. |
| O02 | Каждый старый автор сохраняется после миграции; существующие статьи и редакторские права не теряются. |
| O03 | Подпись сохраняет состав и порядок авторов; профиль содержит все статьи соответствующего человека. |
| O04 | После обработки события поиск находит статью по каждому соавтору; сохранённая проекция соответствует данным. |
| O05 | Экспорт передаёт весь состав и порядок, даже если сигнатура функции осталась прежней. |
| O06 | Соавторство само по себе не разрешает редактирование. |
| O07 | Повтор события не создаёт повторного результата; незавершённая доставка остаётся видимой. |
| O08 | Исключение изображения имеет применимое основание и перестаёт действовать при изменении его предпосылок. |
| O09 | Приёмка относится к точному кандидату и актуальной базе; обязательное неизвестное запрещает её. |
| O10 | Продолжение сохраняет открытые обязательства и применимость прежних оснований. |

JSON содержит ожидаемые состояния после миграции, после изменения статьи и после обновления индекса. Это разные стадии. Сохранение новых данных при старой проекции ещё не является завершением перехода. Приёмка исходника также не означает автоматическую миграцию рабочих данных: опыт исполняет переход только над подготовленной тестовой копией.

## 3. Граф до задания и граница изображения

Исходный граф содержит существующие отношения: редактор пишет данные и создаёт событие; индексатор потребляет событие; поиск читает индекс; экспорт и подпись используют авторство. Контракты требуют полного сохранения атрибуции уже при единственном авторе. Они не пишутся после обнаружения провала, чтобы сделать ответ задним числом очевидным.

Перед предъявлением измерительных заданий фиксируются снимок проекта, граф, контракты, извлекатели и первоначальные основания. Публикуемые здесь примеры служат открытыми проверками. Для измерения переноса пользы независимый проверяющий готовит закрытые варианты заданий; исполнитель не получает их решения при подготовке графа. Все затраты подготовки учитываются.

В базовом случае `image_pipeline@1` вызывает только `image_resize@1`; преобразование получает байты и размеры, не обращается к авторству. Его внутренности могут быть исключены по действующему основанию. Отдельный вариант добавляет watermark: `image_pipeline@2` вызывает `image_watermark`, который наносит имена авторов. Прежнее основание исключения всего конвейера устаревает. Watermark входит в анализ; неизменённые внутренности чистого resize по-прежнему могут оставаться снаружи. Различие названий компонентов не считается основанием изоляции.

## 4. Набор случаев

| Случай | Воздействие и требуемое наблюдение |
|---|---|
| C01 Основное изменение | Миграция, назначение двух авторов, доставка события, подпись, профиль, поиск и экспорт соответствуют фикстурам. |
| C02 Неверные авторы | Пустой список, повтор и неизвестный человек отвергаются; данные и очередь событий не меняются. |
| C03 Отдельные полномочия | `u_boris` не получает право изменения от своего появления среди авторов. |
| C04 Потеря автора в экспорте | Функция всё ещё возвращает строку, но JSON внутри содержит только первого автора. Типизация успешного результата недостаточна; приёмка запрещена. |
| C05 Исчезнувшее ребро | Дефектный экспорт заменён константой, старое ребро чтения исчезает из нового графа. Анализ сохраняет прежнего потребителя через объединение графов; удаление ребра не закрывает O05. |
| C06 Новая сессия | Работа прервана до закрытия поиска и экспорта. Новый исполнитель получает O04/O05 открытыми и не принимает кандидат по одному пересказу. |
| C07 Изменившийся head | Приёмка подготовлена от S0, текущая база уже Sx. Возвращается `STALE_BASE`; head не перезаписывается. |
| C08 Устаревшее исключение | Добавлен watermark, но кэш предлагает прежнее заключение об изображениях. Изменённая предпосылка делает его неприменимым. |
| C09 Старая проекция | После заявленного завершения обновления статья содержит двух авторов, индекс остался прежним. Поиск Бориса теряет `a_101`; переход не принимается. |
| C10 Безопасная локальная правка | Разделитель подписи меняется с « · » на « / ». Неизменные данные, индекс и экспорт не переписываются; их внутренности исключаются по применимым контрактам. |
| C11 Исчерпан анализ | Бюджет закончился до обработки экспорта и индексатора. Сохраняется frontier, статус неполный, приёмка запрещена. |
| C12 Недоступный предмет | Обязательная реализация экспорта недоступна для чтения и нет достаточного иного основания. O05 остаётся неизвестным. |
| C13 Повтор события | Две доставки одного ID создают одну завершённую запись inbox и один набор записей индекса. |

Для C04/C05/C09 дефект подготавливает проверяющий. Успех состоит в обнаружении дефекта и отказе приёмки, а не в обязательном автоматическом исправлении. Независимый оракул проверяет и конечное поведение, и обязательные записи анализа: например, C05 должен сохранить источник связи из старого графа.

## 5. Сравнение A/B/C

**A — сильный обычный подход.** Предлагаемый исходный вариант: TypeScript, его компилятор и языковой сервер, структурные операции, тесты, поиск и хорошо организованные пакеты контекста. Выбор закрепляется T01 с учётом сопоставимости программ.

**B — тот же обычный язык с сопоставимой моделью связей.** Добавляются аналогичные контракты, происхождение данных, граф и сохранение обязательств. Это отделяет полезность среды от полезности собственного языка.

**C — bagaev в объявленном профиле.** Допустим эталонный интерпретатор. Сравниваются одинаковые наблюдаемые обязательства, а не одинаковое число файлов или строк.

Все варианты получают одинаковые бизнес-правила, данные, задачи, модель и ограничения попытки. Версии модели и инструментов фиксируются; порядок запусков перемешивается. B и C имеют сопоставимую исходную информацию о связях. Проверяющий не добавляет одному варианту подсказки, отсутствующие у другого.

Предлагаемый пилот — три независимые попытки каждого варианта с полным зафиксированным набором случаев. Это предложение объёма первой проверки, не достаточная статистика для общего превосходства. T01/T15 **до измерения** закрепляют число попыток, лимиты токенов, времени, стоимости, условия остановки и пороги практического преимущества. Менять пороги после просмотра результатов запрещено.

## 6. Измерение и критерии

Обязательный критерий корректности пилота: **ноль ложных приёмок на перечисленных проверяемых дефектах и неизвестных условиях**. Он относится к данному набору, профилю и границам; это не гарантия полноты произвольной программы. Правильные C01/C10/C13 должны допускать завершение при выполненных обязательствах: отказ от всего не считается успехом.

Считаются пропущенные обязательства, лишний контекст, ложные приёмки, необоснованные отказы, завершённые задачи, общее время, токены, инструментальные затраты и человеческое участие. Отдельно учитываются первоначальное описание связей и их поддержание после изменения. Размер одного пакета не заменяет суммарного чтения во всех шагах. Внутренняя работа анализаторов также входит в стоимость.

Один промах показывает провал конкретной проверки. Он не опровергает все возможные реализации идеи. Требование читать весь проект оценивается отдельно для C10: большая область основного изменения сама по себе ожидаема.

## 7. Отчёт и текущее состояние

Иллюстрация отчёта для C11, **не вывод инструмента**:

```json
{
  "illustrative": true,
  "status": "INCOMPLETE",
  "candidate_label": "S1",
  "in_scope_obligations": ["O04", "O05"],
  "frontier": ["E.indexer", "E.export"],
  "reason": "ANALYSIS_BUDGET_EXHAUSTED",
  "acceptance_allowed": false
}
```

Обозначения S0/S1/Sx — метки примера, не вычисленные идентификаторы снимков. Будущий протокол подставляет точные реальные ссылки, сохраняет запросы, контекст каждого шага, результаты проверки, основания исключений и записи приёмки. Числовые показатели до запуска остаются `null`.

| Вариант | Исполненные попытки | Ложные приёмки | Стоимость | Статус |
|---|---:|---:|---:|---|
| A | — | — | — | NOT_RUN |
| B | — | — | — | NOT_RUN |
| C | — | — | — | NOT_RUN |

Выход T15 — воспроизводимый пакет данных и отчёт с фактическими ограничениями. Если B даёт тот же результат дешевле C, польза собственной языковой основы не подтверждена этим опытом. Если C выигрывает, следующий шаг — повтор на новых задачах с сохранением стоимости обслуживания; один успешный пример не закрывает всю исследовательскую программу.
