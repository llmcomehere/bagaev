# LEX-1 — лексика исходника bagaev

**r26 · контракт V1** (решения D66, D67, D71, D72 — [07-decisions.md](../architecture/07-decisions.md#решения-r25)). Документ задаёт, как байты исходного файла превращаются в токены. Грамматику задаёт [grammar.ebnf](grammar.ebnf), смысл конструкций — [surface.md](surface.md). Коды диагностик — из реестра [DIAG-1](../diagnostics/registry.json).

Каждое правило имеет идентификатор `LEX-nn`. На него ссылается [манифест соответствия](../conformance-manifest.json).

## 1. Кодировка и символы

**LEX-01. Кодировка.** Исходный файл — строгий UTF-8 без BOM.
- Некорректная последовательность (overlong, суррогат, усечение, значение > U+10FFFF) → `INVALID_UTF8` с байтовым смещением первого неверного байта.
- BOM в начале файла → `SOURCE_BOM`.
- Замена на U+FFFD не выполняется.

**LEX-02. Нормальная форма.** Текст файла обязан быть в NFC (Unicode 16.0). Иначе — `SOURCE_NOT_NFC` с первым ненормализованным диапазоном. Инструменты нормализуют только по явной команде форматтера. Сравнение имён и строк идёт по кодовым точкам без нормализации ([data-values.md §7](data-values.md#7-string-bytes-и-границы-unicode)).

**LEX-03. Запрещённые символы.**
- **Во всём файле**, включая строки, байтовые литералы и комментарии, запрещены управляющие символы (категория Cc: C0, DEL, C1), кроме табуляции U+0009 и переводов строк (LEX-04), а также U+2028 и U+2029 → `FORBIDDEN_CHARACTER`. Управляющий символ в значении строки задаётся экранированием.
- **Вне строк и комментариев** пробельные символы — только U+0020, U+0009 и переводы строк. Другие символы категорий Zs и Cf, например U+00A0 или U+200B, → `FORBIDDEN_CHARACTER`. Остальные символы, которые не начинают токен LEX-07…LEX-14, → `UNEXPECTED_CHARACTER`.
- Внутри строк и комментариев допустимы все прочие scalar values, включая Zs и Cf, кроме символов управления направлением.
- Символы управления направлением текста U+061C, U+200E, U+200F, U+202A–U+202E, U+2066–U+2069 запрещены **везде**, включая строки и комментарии → `BIDI_CONTROL_IN_SOURCE`. В строковом значении их можно задать только экранированием `\u{…}` (LEX-09).

**LEX-04. Переводы строк.** Перевод строки — LF или пара CRLF. Одиночный CR → `STRAY_CR`. Перевод строки, как и прочие пробельные символы, на смысл программы не влияет: значимых отступов нет.

## 2. Пробелы и комментарии

**LEX-05. Trivia.** Пробелы, табуляции, переводы строк и комментарии — trivia. Они сохраняются в lossless CST, но не входят в поток токенов грамматики.

**LEX-06. Комментарии.**
- `//` до конца строки — обычный комментарий.
- `///` — документирующий: он привязывается к следующей декларации (surface.md §3).
- Блочных комментариев нет.

## 3. Идентификаторы и ключевые слова

**LEX-07. Идентификатор.** Первый символ — XID_Start или `_`, далее XID_Continue (UAX #31, Unicode 16.0); русские имена допустимы. `_` в одиночку — отдельный токен «пустое имя», а не идентификатор. Идентификаторы сравниваются по кодовым точкам. Смешение письменностей и визуально похожие символы в V1 не проверяются.

**LEX-08. Зарезервированные слова** (16, не могут быть именами):

```text
module use as pub fn let if else match return emit and or not true false
```

Использование зарезервированного слова как имени → `RESERVED_WORD_AS_NAME`.

**Контекстные слова** — идентификаторы, которые имеют особый смысл только в своей позиции грамматики. В остальных местах это обычные имена; например, поле может называться `type` или `table`.

```text
type record enum opaque entity contract about rule purpose terms not_about
store table derived_from event command handler query migration on test
uses reads writes emits host implements requires checks supersedes
```

## 4. Литералы

**LEX-09. Строка** `"…"`: однострочная. Перевод строки до закрывающей кавычки → `UNTERMINATED_STRING`.

Экранирования: `\n`, `\t`, `\r`, `\\`, `\"`, `\0` и `\u{X…}` (1–6 шестнадцатеричных цифр). Значение `\u{…}` обязано быть Unicode scalar value, а не суррогатом. Любое другое экранирование или суррогат → `INVALID_ESCAPE`.

Значение литерала — последовательность scalar values ([data-values.md §7](data-values.md#7-string-bytes-и-границы-unicode)).

**LEX-10. Байты** `b"…"`. Допустимы печатные ASCII U+0020–U+007E, кроме `"` и `\`. Экранирования: `\xHH`, `\n`, `\t`, `\r`, `\\`, `\"`, `\0`. Символ вне ASCII → `INVALID_BYTE_LITERAL`.

**LEX-11. Целое.**
- Цифры — только ASCII `0-9`; символы Nd других письменностей числа не начинают (LEX-03, `UNEXPECTED_CHARACTER`).
- Десятичное `0` или `[1-9][0-9_]*`; шестнадцатеричное `0x[0-9a-fA-F][0-9a-fA-F_]*`.
- Число, за которым сразу следует буква, цифра или `_`, — `MALFORMED_NUMBER` на весь участок: `123abc`, `0x1g`.
- `_` допускается только между цифрами, не подряд и не в конце → `MALFORMED_NUMBER`.
- Ведущий ноль у десятичного: `0`, за которым идёт цифра или `_` (`007`, `0_1`), → `LEADING_ZERO`.
- Знака в литерале нет: минус — оператор (surface.md §5).
- **Лексер** принимает значения до 2^63 включительно; больше → `INT_LITERAL_OUT_OF_RANGE` (фаза `lex`).
- **Разбор** принимает значение ровно 2^63 (`9223372036854775808` или `0x8000_0000_0000_0000`) только как непосредственный операнд унарного минуса: так записывается Int64::MIN. Иначе → `INT_LITERAL_OUT_OF_RANGE` (фаза `parse`). Поэтому лексика не зависит от синтаксиса.

**LEX-12. Нет плавающей точки.** Последовательность цифр с точкой и цифрами после неё (`1.5`, `2.0`) или с экспонентой (`1e9`) → `UNSUPPORTED_FEATURE` с `feature_id: V1-P01` (D71). Это правило отличает такие формы от обращения к полю: `xs.0` недопустимо, а `a.b` — это обращение к полю.

**LEX-13. Булевы значения** `true` и `false` — зарезервированные слова. Unit записывается как `()` (это две пунктуации, не литерал).

## 5. Пунктуация и операторы

**LEX-14.** Токены пунктуации; при разборе выбирается самый длинный совпадающий:

```text
{  }  (  )  [  ]  ,  ;  :  .  ..  ->  =>  =  ==  !=  <  <=  >  >=
+  -  *  /  %  ++  ?  @  |  !  _
```

`!` встречается только перед именем эффект-переменной (`<T, !e>`); `!=` — оператор неравенства. Любой другой символ → `UNEXPECTED_CHARACTER`.

## 6. Координаты

**LEX-15.** Каждый токен и каждая диагностика несут полуоткрытый диапазон байтов `[start, end)` в точном файле (DIAGNOSTIC-PIPE-0.1, [diagnostics.md](../toolchain/diagnostics.md)). Строки и столбцы — только представление для человека. Конкатенация всех токенов и trivia файла побайтно равна исходному файлу.

**LEX-17. Диапазон лексической диагностики** — что покрывает `span`:

| Код | Диапазон |
| --- | --- |
| `SOURCE_BOM` | `[0, 3)` |
| `INVALID_UTF8` | первый неверный байт, `[k, k+1)` |
| `SOURCE_NOT_NFC` | сегмент нормализации вокруг первого расхождения с NFC. Начало — последний символ с ccc = 0 не правее первой позиции расхождения. Конец — первый следующий символ с ccc = 0, не включая его. Для `e` + U+0301 перед `"` — оба символа, 3 байта |
| `FORBIDDEN_CHARACTER`, `BIDI_CONTROL_IN_SOURCE`, `STRAY_CR`, `UNEXPECTED_CHARACTER`, `INVALID_BYTE_LITERAL` | один символ |
| `UNTERMINATED_STRING` | от открывающей кавычки (или `b`) до конца строки, без перевода строки |
| `INVALID_ESCAPE` | вся escape-последовательность, начиная с `\`: `\q` — 2 байта, `\u{D800}` — 8. Для `\u{…}` с ошибкой внутри скобок — до закрывающей `}` на той же строке, а без неё — `\u`. Для `\x` — `\x` и до двух следующих символов |
| `MALFORMED_NUMBER`, `LEADING_ZERO`, `INT_LITERAL_OUT_OF_RANGE` | весь числовой токен, включая `0x` и `_` |
| `UNSUPPORTED_FEATURE` (число с точкой или экспонентой) | вся форма, например `1.5` или `1e9`, `data.feature_id = "V1-P01"` |

**LEX-16. Порядок лексических ошибок.** Лексер идёт слева направо. Каноническим ответом служит первая ошибка по смещению; при равных смещениях порядок определяют номера правил LEX-01…LEX-14. Восстановление продолжает разбор с границы следующего токена, чтобы IDE могла показать остальные ошибки. Такие дополнительные ошибки не делают файл принятым.
