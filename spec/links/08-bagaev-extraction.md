# LINKS-1 — связи bagaev: извлечение, граф, влияние, ContextPack

**r33 · WORKING_DESIGN (D11, D12, D82–D84, EFF-12, EFF-13).** Документ переводит общий механизм [01](01-records-and-invariants.md)–[04](04-acceptance.md) в термины bagaev и задаёт то, что исполняет эталон: `ref/bagaev_ref/links/`. Правила имеют идентификаторы `LNK-08-nn`. Главы 05–07 остаются исследовательскими профилями. Полный LNK-I01 (UseSummary, DeltaSummary, фасеты, отслеживаемые запросы) здесь сужен до структурного анализа (§8).

## 1. Назначение

**LNK-08-01.** Граф строится из **проверенной** программы (CHECK-1) и её BIR-1. Программа, не прошедшая проверку, графа не имеет: ответ — `PRELAUNCH` с её диагностиками. Извлечение ничего не исполняет и ничего не пишет (T14-C01). Исключение — явный `bag graph --save` (§7) и `--with-tests` анализа влияния: тесты исполняются на хранилищах в памяти (HST-18) как свидетельства для D83(a).

## 2. Узлы и ревизии

**LNK-08-02. Узел** — каждое место SURF-07 (`@id`):
- модуль;
- декларация верхнего уровня;
- поле, вариант, таблица, правило.

Поля узла: `id` (EntityId), `kind`, `name` (полное имя), `file`, `span`, `pub`, `rev`, у функций и точек входа ещё `sig` и `head` — диапазон текста до тела (интерфейс для ContextPack).
- `rev` = `digest("decl-rev", "1", канон)`. Канон — дерево разбора элемента без мест, комментариев и документации; имена, литералы, атрибуты `@id`, связи и тело входят.
- У модуля канон — заголовок и список `use`.
- `sig` = `digest("decl-sig", "1", …)` от имени, обобщений, параметров, результата, ряда и связей, без тела. Это ревизия интерфейса для D83(a).
- Ревизия **локальная**: изменение вызываемой функции меняет только её `rev`. Транзитивность даёт распространение (§5), а не хеш. Поэтому рекурсивная группа модуля (BIR-01) хешируется без циклов.
- Переименование с тем же `@id` — та же сущность с новой ревизией. Смена `@id` — удаление и создание (SURF-07).

## 3. Рёбра

Каждое фактическое место даёт отдельное ребро (EFF-12): `{id, kind, src, dst, site{file, span}, provenance{origin, rule, extractor}, qualifiers?}`. `origin` — `structural` (извлечено) или `declared` (написано автором, SURF-15). `id` = префикс `digest("edge", "1", {kind, src, dst, site})`.

| Правило | Вид | Источник → цель | Откуда |
| --- | --- | --- | --- |
| LNK-08-03 | `calls` | функция-владелец → функция группы | `Global` в позиции вызова `Call` в теле (включая тела лямбд владельца) |
| LNK-08-04 | `references` | владелец → функция | `Global` вне позиции вызова: функция как значение |
| LNK-08-05 | `uses_type` | декларация, поле, вариант, таблица → номинальный тип | типы сигнатуры и **всех выражений тела** по результатам проверки; по паре (источник, тип) одно ребро, место — первое |
| LNK-08-06 | `reads` / `writes` / `emits` | владелец → таблица / событие | `Perform` `std.store.*` и `event.emit@1` с ресурсом (`qualifiers.op` — операция) |
| LNK-08-07 | `consumes` | обработчик → событие | тип параметра `handler` |
| LNK-08-08 | `implements` / `requires` / `checks` / `about` / `derived_from` / `supersedes` | декларация → сущность, контракт или правило | синтаксис связей SURF-11, SURF-12, SURF-15; `origin: declared` |
| LNK-08-09 | `migrates` | миграция → таблица | `migration … on S.t` |
| LNK-08-10 | `defines` | контейнер → член | модуль → декларации; тип → поля и варианты; событие → поля; store → таблицы; контракт → правила |

- Вызов через значение fn-типа (`f(n)` с параметром `f`) отдельного ребра не даёт. Функция может попасть в значение только через `references` или лямбду владельца, и эти места уже дают рёбра. Поэтому `calls` ∪ `references` полны.
- Функции `std` — внешние цели `std:<полное имя>` без узлов: вызов (`Global` std или `Prim std.*`) даёт `calls`, значение — `references`. Поэтому смена разрешения имени (`use std.i64.{add as op}` → `{sub as op}`) меняет цель ребра и делает владельца семенем (LNK-08-13).
- Операторы (`op.*`) и конструкторы рёбер не дают: операторы — синтаксис и входят в `rev`, типы конструкторов видны через `uses_type`.
- `supersedes` — ребро к строке ID с `qualifiers.verified: false` и пробел `SUPERSEDES_HISTORY_UNCHECKED`. Сверка с историей принятых снимков — Ф6.
- Объявленный, но неиспользуемый атом ряда ребра не даёт (EFF-04, EFF-12): он записывается в `unused_atoms` как «объявленная граница без места».

## 4. Граф и покрытие

**LNK-08-11. Граф** — запись BAG-CJSON-1 `{format: "bagaev-graph/1", extractor_rev, source, nodes, edges, coverage, gaps, unused_atoms}`:
- узлы упорядочены по EntityId, рёбра — по `(kind, src, dst, file, start, id)`;
- `source` — дайджест набора исходников; GraphRef = `digest("graph", "1", граф)`;
- схема — [graph.schema.json](graph.schema.json);
- `extractor_rev` = `links-1@1+` и префикс дайджеста кода, от которого граф зависит: извлекатель, проверка, понижение, интерфейс std. Смена любого из них — новый граф и полное извлечение;
- прямой и обратный индексы — представления одного списка рёбер (links/01 §9 инв. 2).

Граф хранится вне снимка (D84): `.bagaev/graph/<source>/<extractor_rev>.json`. Пока снимков нет (Ф6), ключом служит дайджест исходников. Ссылки на снимок внутри графа нет (links/02 §2).

**CoverageRecord** — для каждого вида рёбер `COMPLETE | PARTIAL` с основанием (EFF-13):
- все виды, кроме `supersedes`, — `COMPLETE`. Основания: таблицы и события — статические пути (EFF-07); пользовательского FFI нет (D87); реестр адаптеров пуст (EFF-02); функция как значение видна по `references`; типы выражений известны проверке;
- `supersedes` — `PARTIAL`.

Эти основания полноты относятся к bagaev. Обязательны записи всех переносящих видов LNK-08-12; отсутствие записи не доказывает отсутствие рёбер. Явное исключение профиля `links-ts@1`: нет вида `migrates` (в TypeScript нет декларации migration, слой migrations — обычный TS-код). Если ребро такого вида всё же есть, его покрытие также обязательно. В TypeScript вызываемые переменные (arrow/function expression и алиасы) — узлы `fn`; вызов даёт `calls`, алиас сохраняет `references` к исходной декларации. Каждая переменная в общей декларации владеет своим телом. `PARTIAL` относится ко всему заявленному scope: текст причины не доказывает локальную полноту остальных сущностей.

Внешние границы: вызывающие точек входа вне программы и `std`.

**Пробелы** (`gaps`):
- `EXTERNAL_CONSUMERS` у каждой `pub command|query` — её потребители вне программы не перечислимы (T08-C03);
- `SUPERSEDES_HISTORY_UNCHECKED`.

Неизвестная цель получает запись пробела, а не выдуманный узел (links/01 §3).

**LNK-08-18. Инкрементальное извлечение.**
- Модуль переизвлекается, если изменился его штамп: байты модуля, байты всех модулей, импортируемых транзитивно, и `extractor_rev`.
- Рёбра и пробелы остальных модулей берутся из прежнего графа по файлу места, узлы строятся всегда.
- Смена `extractor_rev` — полное извлечение.
- Норма — равенство байтов с полным извлечением; экономия не заявляется. Проверка — `conformance/tools/incremental_vs_full.py`: цепочка правок, сравнение графов и ответов запросов, внесение неисправностей (штамп без импортов, без транзитивных импортов).

## 5. Влияние

**LNK-08-12. Направление зависимости.** Для каждого вида задано, какой конец зависит от другого:
- `calls`, `references`, `uses_type`, `reads`, `consumes`, `defines` — источник зависит от цели;
- `writes`, `emits`, `migrates` — цель (содержимое таблицы, событие) зависит от источника.

Влияние не переносят:
- `defines` модуля: модуль — пространство имён;
- `reads` / `writes` / `emits` теста: тест работает на своей копии хранилища (HST-18) и рабочие таблицы не связывает;
- декларированные связи: они дают обязательства (LNK-08-17), а не распространение по коду.

**LNK-08-13. Семена.** Сравниваются base и candidate по EntityId:
- `added` / `removed` — сущность есть только в одной версии;
- `changed` — `rev` различается;
- `edge-added` / `edge-removed` — добавлено или снято переносящее ребро. Семенем становится тот конец, который от ребра зависит (если он ещё не семя).

Семена упорядочены по EntityId.

**LNK-08-14. Распространение** (упрощённый LNK-I01, D12).
- Рабочий граф — объединение рёбер base и candidate с метками сторон. Снятое в кандидате ребро продолжает переносить влияние (T09-C01).
- Worklist — очередь с ключом `(расстояние, режим, EntityId, порядок вставки)`, режим `AFFECTED` < `UNKNOWN`.
- Каждое извлечение, которое меняет состояние, — один шаг бюджета `--analysis-budget`.
- Состояние монотонно: `AFFECTED` сильнее `UNKNOWN`; повторное достижение не обрабатывается. Поэтому циклы конечны и самообоснования нет (T09-C02).
- Сущности из `--unavailable` засеваются в `UNKNOWN` (`ACCESS_BLOCKED`) **до обхода**, даже если влияние до них не дойдёт: их содержимое нельзя читать, поэтому исключить их нельзя. Всё, что от них зависит, — TOP (`DEPENDS_ON_UNKNOWN`); известно затронутое сильнее и повышает `UNKNOWN` до `AFFECTED`.
- Бюджет кончился — статус `INCOMPLETE`:
  - достигнутые, но не обработанные сущности — `frontier` с расстоянием и основанием;
  - все прочие — `unknown` (`ANALYSIS_INCOMPLETE`);
  - исключений нет (T09-C03).
- Любой переносящий вид CoverageRecord неполон в base или candidate — статус `INCOMPLETE`, известные пути сохраняются, прочие сущности остаются `unknown` (`COVERAGE_PARTIAL`, со стороной, видом и причиной). Исключений D83 нет; отсутствие известного пути при пропущенных рёбрах не доказывает независимость. Это относится и к анализу без семян.

**LNK-08-15. Сертификат D83(a) — интерфейсный контракт** закрывает **обязательство** «Y полагается на правило R» (пару `requires`, LNK-08-17), но не отношение. Выходы Y — его записи, события, результат — остаются в области: закрытие обязательства не закрывает выходной delta (links/03 §3). Условия:
1. R и Y — не семена; Y `requires` R в обеих версиях;
2. есть затронутые провайдеры — сущности в области, которые `implements` R. Каждый есть в обеих версиях, его `sig` не изменился, связь `implements` R сохранилась;
3. у R в базе есть тесты `checks`. Каждый из них есть в кандидате с той же ревизией, не семя, по-прежнему `checks` R и на кандидате даёт PASS (свидетельства `--with-tests`). Тесты кандидата, которых нет в базе, свидетельством не служат;
4. замыкание зависимостей этих тестов содержит каждого затронутого провайдера: тест действительно исполняет то, что изменилось.

Основание записывает предпосылки: ревизию Y, ревизию R, `sig` и ревизии провайдеров, ревизии тестов с результатом. При перепроверке на другой версии любое расхождение даёт `stale`: новая ревизия провайдера требует новых свидетельств. Без свидетельств сертификата нет.

**LNK-08-16. Сертификат D83(b) — нет пути зависимости.** Только при статусе `COMPLETE` и полном покрытии переносящих видов обеих версий каждая сущность, до которой влияние не дошло, исключена с основанием `D83b-no-dependency-path`. Его предпосылки:
- ревизия сущности;
- дайджест её замыкания зависимостей `digest("dependency-closure", "1", [[id, rev]…])`;
- перечень видов рёбер с полным покрытием.

Перепроверка основания на другой версии (`why --recheck`) пересчитывает предпосылки, включая покрытие: `applicable` или `stale` (T09-C04, C08). PARTIAL не позволяет ни выдать, ни подтвердить сертификат. Неполное замыкание также не служит основанием переноса свидетельства `same-closure` (CHG-12).

**LNK-08-17. Обязательства.** Каждое декларированное ребро (`implements`, `requires`, `checks`, `about`, `derived_from`) — пара «смысл (сущность, контракт, правило) — декларация». Её статус:
- `open` — смысл семя (изменён, добавлен, удалён) или декларация в области;
- `excluded_with_basis` с основанием D83(a) — пара `requires`, закрытая сертификатом LNK-08-15 (в отчёте — поле `basis`);
- `unknown` — декларация unknown или во frontier, либо анализ неполон;
- `excluded_with_basis` (D83b) — иначе.

Пары берутся из обеих версий и помечаются сторонами. Пара, существующая только в base, остаётся открытой, если её декларация в области (C05).

Тесты к прогону — тесты в области и тесты `checks` открытых смыслов.

**Отчёт** (OUT-05):
- `status`: `COMPLETE` или `INCOMPLETE`;
- `seeds`, `in_scope` (с расстоянием и основанием `via{from, kind, side, edge}`), `excluded_with_basis` (только D83b), `unknown` (с причиной), `frontier`, `obligations`, `tests_to_run`, `gaps` (пробелы сущностей в области), `coverage_gaps` (неполные переносящие виды по сторонам);
- `readiness`:
  - `BLOCKED` — анализ неполон или есть unknown;
  - `ELIGIBLE_IF_ALL_OBLIGATIONS_PASS` — есть открытые обязательства;
  - `NO_OPEN_OBLIGATIONS` — открытых обязательств нет.

Решение о приёмке остаётся за Ф6.

**Объяснения:**
- `why --affected` — путь от семени по `via`;
- `why --not-affected` — основание исключения, а для unknown — причина.

## 6. ContextPack

**LNK-08-19. Обязательная оболочка** входит всегда: статус и готовность отчёта, GraphRef обеих версий, семена, **все** не исключённые обязательства, unknown и frontier. Обязательство не теряется из-за бюджета (T11-C04). Если оболочка больше бюджета — отказ `MANDATORY_ENVELOPE_TOO_LARGE`.

**LNK-08-20. Раскрытие.** Кандидаты получают ключ `(приоритет, расстояние, EntityId)`:

| Приоритет | Элементы | Покрытие |
| --- | --- | --- |
| 0 | семена в области | `expanded`: точный текст версии (кандидата, у удалённых — базы) с ревизией |
| 1 | смыслы открытых обязательств | `expanded` |
| 2 | прочие сущности области | `expanded` |
| 3 | исключённые зависимости сущностей области | `boundary`: интерфейс (текст до тела) и сертификаты основания |
| 4 | unknown и frontier | `blocked` (`ACCESS_BLOCKED`) или `pending` (`UNKNOWN`, `ANALYSIS_FRONTIER`) с действием |

Повторная сущность занимает первое место.
- В бюджет входят оболочка, элементы и записи покрытия; место под отметку обрыва резервируется. Если не помещается даже оболочка с этим запасом — `MANDATORY_ENVELOPE_TOO_LARGE`.
- Элементы добавляются по порядку, пока помещаются. На первом не поместившемся страница кончается: сводная запись `pending` / `BUDGET` с позицией и числом оставшихся, `next_cursor` — эта позиция.
- Элемент, который не помещается даже на пустую страницу, заменяется интерфейсом (`boundary`, причина `ITEM_TOO_LARGE`) или отмечается `pending` / `ITEM_TOO_LARGE`; обход идёт дальше. Курсор всегда продвигается.
- Продолжение с тем же курсором даёт следующую страницу.
- Измеритель — `utf8-bytes/4@1`: ⌈байты BAG-CJSON-1 / 4⌉. Ранжирование — `links-1-context@1`. Оба названы в ответе (T11-C05).
- `ready_for_step` истинно, только если отчёт `COMPLETE`, unknown нет, нет `pending` и `blocked` и раскрыта первая страница целиком.
- Блокеры: `ANALYSIS_SCOPE_INCOMPLETE`, `ACCESS_BLOCKED`, `CONTEXT_INCOMPLETE` — обрыв по бюджету или `ITEM_TOO_LARGE` (T11-C03).

## 7. Команды и наблюдения

- `bag graph <корень> [--save]` — граф с GraphRef;
- `bag relations <корень> <сущность> [--direction in|out|both] [--kinds …]` — рёбра с provenance, покрытие видов, пробелы;
- `bag impact <база> <кандидат> [--analysis-budget N] [--unavailable id,…] [--with-tests]` — отчёт §5;
- `bag context <база> <кандидат> --budget N [--cursor C] …` — ContextPack §6;
- `bag why <база> <кандидат> <сущность> --affected | --not-affected [--recheck <корень>]`.

Сущность (и элементы `--unavailable`) указывается EntityId или полным именем; неизвестная — `UNKNOWN_ENTITY`. Случаи conformance фаз `graph`, `impact`, `context` наблюдают проекции этих ответов по именам сущностей ([conformance/README.md](../../conformance/README.md)).
